## SPEC 第 9 節的原方向、為什麼改、改成什麼

- **原方向：** 「回合制：三種貨物的價格會波動，60 回合內低買高賣」。
- **照字面做會怎樣：** 如果價格是外生的隨機波動，兩個人各自猜同一條曲線：我買不影響你、你賣不影響我，AI 變成「分數標竿」而不是對手（`DESIGN-AI-FUN.md` 3.1「沒有選擇的 AI」；老闆提醒的「各自做生意」）。
- **改成什麼：**
  1. **價格 = 公開的行情曲線 + 雙方買賣留下的偏移。** 曲線是種子決定、全程公開的（預告型，沒有任何隨機驚喜），**你們兩個的買賣會把偏移推高（買）或壓低（賣）**，所以「你買貴了它就賣給你」是真的：你把價格推上去，它的存貨賣得更好。
  2. **雙方的存貨與每一筆買賣全部公開**：「它在囤什麼」看得到；它囤了多少、曲線什麼時候到頂，就推得出它什麼時候要倒貨、價格會被壓下來多少。這是第 4.1 節「歷史進 state、`evaluate` 做對手建模」的用法。
  3. **回合數 60 → 24。** 理由：60 回合要在 60 秒內打完，每個決定只有 1 秒，而每回合要讀三個價格、兩份存貨與曲線；24 回合每回合約 2 秒，讀得完。這是 SPEC 數字的修改，在這裡明寫。

## 類型（`docs/DESIGN-AI-FUN.md` 第 2 節）

**互相牽制型**（共用價格）＋ **互相讀取型**（同時出手、對手建模）。性格可辨識型也成立（性格表）。

### 驗收題：AI 做的哪一個選擇會改變玩家的最好做法？

1. **它現在買哪一種貨。** 它連買兩回合布 → 布的偏移被推高 → 你手上有布就該賣、沒有布就別買；你若繼續買布，付的是被它推高的價格。
2. **它囤了多少、曲線什麼時候到頂。** 它手上 6 件鐵，鐵的行情 4 回合後到頂：它倒貨的那幾回合鐵價會被壓低，你要**比它早賣**，或者**改做別種貨**；你若也囤鐵，就是兩個人擠同一個出口。
3. **它同時選了同一種貨。** 同一回合兩邊都買同一種貨，下一回合價格多 +4；兩邊都賣則 −4。**選不同的貨比較省**，所以你要猜它這一回合會碰哪一種（它也在猜你）。

## 規則

- **貨：** 3 種（穀 0、布 1、鐵 2）。每人開局現金 `CASH = 60`、存貨 0。
- **行情曲線 `base[g][r]`（公開，種子決定）：** 第 g 種貨第 r 回合（0 起算）的基準價。每種貨有一個「旺季」：峰值回合 `peak[g]`，三個峰值從 4 到 17 之間挑，兩兩至少相差 5 回合。
  `base[g][r] = LOW + round((HIGH − LOW) × max(0, 1 − |r − peak[g]| / WIDTH))`，`LOW = 6`、`HIGH = 15`、`WIDTH = 6`。旺季之外價格是 `LOW`。全部 24 回合 × 3 種貨在開局就畫在畫面上（一個小折線圖）。
- **偏移 `dev[g]`：** 整數，雙方買賣留下的痕跡。開局 0。
- **這一回合的價格：** `price[g] = clamp(base[g][r] + dev[g], 2, 20)`。
- **每回合：** 兩邊**同時**選一個動作，一旦鎖定就不能改：**買 1 件某種貨**、**賣 1 件某種貨**、**不動**。
  - 買：付 `price[g] + FEE`，存貨 +1；現金不夠就不能買。賣：得到 `max(1, price[g] − FEE)`，存貨 −1；沒有存貨就不能賣。`FEE = 1`（買賣各一次，來回共 2）。
  - 兩邊都在這個回合的**開局價格**成交（同一個價格，不分先後）。
  - 結算後更新偏移：`net[g] =（兩邊買 g 的件數）−（兩邊賣 g 的件數）`，`dev[g] ← trunc((dev[g] + IMPACT × net[g]) / 2)`，`IMPACT = 2`（往 0 無條件捨去）。
    例：只有一個人買 1 件穀 → 下一回合穀 +1，再下一回合 0；兩個人都買 → 下一回合 +2、再下一回合 +1。
- 24 回合結束：**只算現金**，現金多的贏，一樣多平手。**手上沒賣掉的貨不算錢。**

**為什麼來回買賣沒有白賺的錢（我算過）：** 買一件 + 賣一件手續費共 2，一個人買 1 件讓下一回合價格 +1（`IMPACT 2 ÷ 2`），所以「買了下一回合就賣」是賠 1 左右，不是賺；只有曲線在上升（旺季）、或對手的買賣把價格推高，才賺得到。
這個性質要用測試擋住（見「實作前要驗證的事」：只做來回買賣的劇本，24 回合後現金不可以比 60 多）。

### 回合流程（沿用 H-Q 的作法）

- `prep`（每回合開始 30 tick，只有第一回合 60）→ `choose`（等兩邊鎖定，最長 `CHOOSE_TIMEOUT = 90` tick，超時自動「不動」）→ `locked`（兩邊都鎖定、而且 `choose` 已經過了至少 `MIN_CHOOSE = 30` tick 之後，等 2 tick）→ `result`（開牌，兩邊的買賣與新價格顯示 20 tick）→ 下一回合。
- 一回合最短 30 + 30 + 2 + 20 = 82 tick，最長 30 + 90 + 2 + 20 = 142 tick。整局最長 60 + 24 × 142 ＝ 3468 ≤ 3600（`CHOOSE_TIMEOUT` 取 90 而不是 100，正是為了不超過 `maxTicks`）；最短 24 × 82 ＝ 1968 tick，約 33 秒。
- 鎖定那個 tick 起，**畫面上對方只看到「已鎖定」，看不到它選了什麼**。

## 資訊限制

- **同時出手：不可以偷看對方這回合的選擇。** 對方的 `pending` 在 `result` 之前是祕密的。這是 `DESIGN-AI-FUN.md` 4.2 的牌：**要寫 4.2-a（`evaluate`、`actions` 對對手 `pending` 是盲的）與 4.2-b（四個性格的 `decide`，深度 1、3、6，同一個起點、只有對手的 `pending` 不同，實際按的鍵相同），並且用故意注入的洩漏確認它會紅。**
- **公開的：** 行情曲線、價格、偏移、雙方現金與存貨、過去每回合的買賣紀錄（`history`）。AI 用 `history` 做對手建模，不是偷看。
- 結算在 `step` 裡讀 `pending`（同 H-Q），所以 `evaluate` 對「`result` 階段的真實結算」要目盲：`result` 與 `locked` 階段 `evaluate` 用的是「我的選擇 + 從 `history` 預測的對手選擇」算出的期望，不讀 `last`（真實結算）裡對手的那一半。作法細節照 `docs/cards/H-Q.md`「pending 與結算順序」。

## 預設性格與等級曲線

**搜尋型（`pathfinder`）**，`baseLevel = 2`（SPEC 7.2：4 到 6 張是 2），`symmetric = true`（兩邊規則、現金、曲線完全一樣），不標 `winnerNotByScore`、`seedIndependent` 不標（曲線由種子決定）。方塊的預設是貪心型；**這裡用搜尋型的理由跟 H-Q 一樣：** 要「看得深等於讀得準」，只有搜尋型把 `depth` 接到 `evaluate`（SPEC 7.1，貪心型是一步看，等級 1 與等級 10 只剩亂選的差別）。J、Q、K 以外的牌偏離 SPEC 預設，這是我的建議，要量過才定。

**等級曲線從結算流程長出來（`DESIGN-AI-FUN.md` 5.1）：** 從決定到看見結果要 3 步（鎖定 → `locked` → `result`），所以只有搜尋深度 ≥ 3（等級 4 以上）模擬得到「我這一手對下一回合價格的影響」與「我預測的對手這一手」帶來的期望；等級 1 到 3 只剩「看現在的價格與行情」的反射式買賣。`evaluate` 裡沒有任何「如果等級 ≥ 4」的分支。
**這一條是預期，未量測；量法：等級 1 與等級 10 對同一個對手（例如 `human-model`）的勝率差。**

## 操作

| 鍵 | 動作 |
|---|---|
| 左／上／右 | 選穀／布／鐵 |
| 按住 a 再按左／上／右 | 買那一種 |
| 按住 b 再按左／上／右 | 賣那一種 |
| 都不按 | 不動（到時間自動不動） |

同一個 tick 同時按了 a 和 b：當作沒有動作（避免誤觸）。鎖定之後再按什麼都沒有用。

## state

- `tick`、`maxTicks`、`over`、`winner`、`round`（0 到 23）、`phase`（`'prep' | 'choose' | 'locked' | 'result'`）、`wait`、`idle`（choose 已過幾 tick）。
- `base: readonly number[][]`：3 × 24 的曲線（開局決定，不變，整數）。
- `dev: readonly number[]`：3 個偏移。
- `cash: readonly [number, number]`、`inv: readonly number[][]`（兩邊 × 三種貨）：**已入帳**的。
- `pending: readonly [Trade | null, Trade | null]`：`Trade = { good: 0|1|2; side: 'buy' | 'sell' } | { pass: true }`（還沒鎖定是 `null`）。
- `last`：`result` 階段才有：`{ trades, price, delta }`，下一回合開始前入帳。
- **`history`：已入帳的每一回合 `[人的 Trade, AI 的 Trade]`，最多 24 筆**（固定長度上限；AI 只用最近 `WINDOW = 6` 筆）。
- `salt`、`rng`：給 `evaluate` 在沒有資訊時做平手的隨機選擇（同 H-Q）。
- `bought: readonly [number, number]`、`dumped: readonly [number, number]`：累計買幾件、累計「賣的價格低於 `base` 的件數」（指紋量測用）。

## 動作與評估

- `actions(state, side)`：`choose` 階段而且我還沒鎖定：`[不動, 買穀, 買布, 買鐵, 賣穀, 賣布, 賣鐵]`，其中買不起、沒存貨的不列出（只看自己的現金與存貨，不看對手的 `pending`）。其他階段：`[全放開]`。
- `evaluate(state, side)`：令 `diff = 現金差`。
  - 結束：`gain = diff ± 1000`，`danger = 0`。
  - `prep`／`choose`（我還沒鎖定）：`gain = diff + exitValue(我) − exitValue(對手)`。
  - `exitValue(誰)`：這個人手上每一件貨「還能賣到的期望價」。對第 g 種貨：剩下的回合裡，每一回合 r 的期望賣價 = `base[g][r] − FEE + dev 預期`，再扣擁擠：`− OVERHANG_WEIGHT × (對手手上同種貨的件數 ÷ 剩下的好價回合數)`；取最高的那一個回合，再依「這個人剩下幾回合能賣出幾件」限制最多算 `剩下回合數` 件。
    **對手的存貨與買賣紀錄是公開的**，所以「它囤了鐵」會讓我的鐵 `exitValue` 下降（擁擠），這就是「它在囤什麼」影響我的最好做法的地方。
  - `locked`、`result`：`gain = diff + 我這一手的期望現金變化（對 `predictOpponent` 的分佈取期望）+ 結算後偏移對我的存貨與對手存貨的影響`。**不讀 `last` 裡對手那一半。**
  - **`predictOpponent(history, side)`**（純函式，只讀 `history`，`evaluate` 與畫面共用）：窗口 6 回合，對手每一種動作（7 種）出現次數各加 1 次的平滑，算分佈。再混入一個先驗：「對手傾向做 `exitValue` 增加最多的那一手」（用公開資訊算的 best response，權重 0.5）。**它是對歷史做最佳反應，不依等級分支。**
  - **`danger`**（0 到 1）：「到結束還賣不掉的存貨」。`left = ROUNDS − round`，`unsold = max(0, 我的存貨總數 − left)`（一回合只能賣一件）；再加「旺季已過」的存貨比例；`danger = clamp01(unsold / 3 + 結束前擁擠 / 4)`。
    貪心型不看它；精準型用它排除「再買就賣不完」的動作；賭徒型被它吸引（囤到旺季）；搜尋型用它扣分。
- **不是橡皮筋：** `evaluate` 的分差項（`diff`）是對稱的，沒有「領先者被懲罰」的項；對調兩邊的現金，AI 的選擇不變（測試）。

## 性格表（預測，**全部未量測**）

指紋指標：**結束時沒賣掉的貨（件）**、**賣出價低於基準價的件數（`dumped`，跟著對手倒貨的程度）**、**同一回合選到跟對手同一種貨的比例（碰撞率）**。

| 性格 | 在這張牌上會做的事（預測） | 預期的指紋 |
|---|---|---|
| 貪心型（greedy） | 一步看：現在價格低於基準就買、高於基準就賣，不看對手囤了什麼、也不管賣不賣得完 | 碰撞率高；結束時剩的貨多 |
| 精準型（precise） | 先排除「賣不完」「被對手擠壓」的動作，剩下的選期望最高；倒貨比別人早、數量穩定 | 剩貨最少；碰撞率低 |
| 搜尋型（pathfinder） | 往前看 3 步以上，算我這一手對下一回合價格的影響與我預測的對手；讀你的習慣（你連買兩回合布，它賣布給你的價格） | 預期被你「騙」的空間最大（見下） |
| 賭徒型（gambler） | 被 `danger` 吸引：旺季前囤大量一種貨，賭旺季賣得掉；落後時囤得更兇 | 結束剩貨高、現金起伏最大 |

預期差異（要量到才算數）：結束剩貨，貪心／精準 ≥ 2；碰撞率，貪心／精準 ≥ 1.5（建議值）。

## 為什麼跟 AI 互動起來好玩

具體場面：第 7 回合，布的旺季還有 3 回合到頂。你看到畫面：AI 連續兩回合買布，存貨 4 件布；偏移 +3，布現在比曲線貴 3。
你想：「它在囤布，打算在頂峰附近一起倒；它倒貨的那幾回合布價會被壓下去，我手上的 3 件布賣在它前面比較好。」你第 8 回合就賣布（價格被它推高了），而不是等到旺季頂點。
然後你又想：「它看得到我在賣布，下一回合它會改去囤鐵嗎？」第 9 回合你**假裝**也買布（讓它以為你要跟進），它預測你會買布、下一回合布價會更貴，於是…
**重點是：價格是你們兩個人的買賣寫出來的，你推它、它推你；存貨公開，所以每一次買賣都是一句話。**

- **搜尋型（預設）：** 讀你最近 6 回合；你一直買布它就賣布給你，你換招它會慢兩回合才發現（窗口）。你可以養習慣再反打。
- **貪心型：** 完全不管你囤什麼，常常跟你同一回合買同一種貨（碰撞）；你要做的是避開它。
- **精準型：** 穩定、早賣完；你贏不了它的紀律，只能靠它賣完之後去吃旺季尾巴（它已經沒存貨）。
- **賭徒型：** 它囤大量、押旺季；你**早它一回合倒貨**，或者在它囤到最大的時候去買它不買的貨。

**誠實的疑慮（這張牌最重要的一節）：**
1. **互動的幅度可能太小。** 曲線的旺季（6 到 15）決定了大部分利潤，雙方買賣的 `IMPACT` 只讓價格偏 1 到 4。如果「照曲線買低賣高」的劇本與「會讀對手」的劇本現金差不到 5，這張牌的互動只是裝飾；這時不要做完，改成：把 `HIGH` 降到 11、把 `IMPACT` 提到 3，再量一次；還是不行就回報「D-6 的方向不成立」。
2. **一回合只能做一件事，24 回合的決策量不多**，而且每回合選擇很「對稱」（買穀、買布、買鐵），玩家可能覺得是在填表。「它在囤什麼」要靠玩家去看存貨，畫面要把兩邊存貨與價格偏移畫得一眼讀得懂。
3. **這是方塊裡的紅心。** 沒有共用場地的格子、沒有走位，只有「共用價格」這個共用資源。若老闆認為方塊的靈魂是「共用的格子場地」，這張牌應該被換掉（例如換成「在格子上有 3 個集市、你站著的集市對手買賣價格更差」之類的位置版本；那是另一張牌，我這一輪沒有寫）。
4. **A4 預期沒有鑑別力**（人類模型一步看、不讀對手，被搜尋型壓死）；證據要靠劇本玩家。

## 模板驗收：原型關卡未通過，D-6 按模板不成立（2026-10-08）

**一句話結論：** 照小規格的規則，原型關卡四條裡兩條沒過（讀對手比照曲線只多 −0.4、勝率 46.8%，不是 ≥5 與 ≥60%；照曲線只比空手多 22，不是 ≥40）；小規格自己寫的補救（`HIGH 11`、`IMPACT 3`）也沒過。我另外做了一個真的會讀對手的 AI 原型，在三種規則下量「餵了再破」：**騙的人在平均時機下輸 3 到 15 現金（第二欄），AI 因為「讀」而多賠的只有 0.1 到 3.8（第四欄），第二欄大於第四欄，就是 H-4 的結構。** 所以我沒有寫 `src/games/D-6/`。

這不等於「這個市場沒有東西可讀」：**讀對手對 AI 是強度，不是破綻**（規則 B：會讀的對不會讀的 81% 勝率、多贏 6.7 現金），只是量不到玩家「騙」了它能拿到什麼。細節與原因如下。

### 量法（腳本附在最後，可重現）

- **純規則原型**：只有 `step` 的規則（24 回合、3 種貨、每回合同時一個動作、兩邊在回合開頭的價格成交、手續費 1、最後只算現金），不寫 `Game`、不寫 `evaluate`。種子 0 到 199、兩邊座位互換，每格 400 場。
- **有對手建模的 AI 原型**：把「`evaluate` 在結算之後會算的東西」直接寫成一步最佳反應（等於搜尋型在深度 ≥3 的終點）。價值 = 現金差 ＋ 我的存貨的出清價值 − 對手的存貨的出清價值。出清價值是把每件貨分配到未來不同的回合（一回合只能賣一件）、用預測的價格；**預測價格 = 曲線 + 偏移，偏移用「對手最近 6 回合的買賣、每早一回合乘 0.6」估出來的壓力往前推（每早一回合再乘 0.7）**。對手建模關掉＝壓力設成 0，其餘完全相同（消融）。存貨是承諾：買進的貨按預測價值入帳，要一回合一件賣掉，來回手續費 2，沒賣掉的不值錢。
- **劇本玩家**：「不讀對手」＝同一個引擎但關掉建模（是一個不差的照曲線打的玩家，比下面小規格的手寫曲線腳本強得多）；「會讀對手」＝同一個引擎開著建模；「均勻亂決定」＝從合法動作裡均勻挑；「餵了再破」＝在第 f 回合起連續 k 回合（k＝1 騙一次、2 騙兩次）買進接下來旺季最高的那種貨，之後（可選：接著連 k 回合賣掉它）照「不讀對手」的引擎打；f 取 0、3、6、9、12 × 有沒有接著賣，共 20 種時機，**報平均與最好的一種**（最好的一種是挑出來的，偏向玩家）。

### 四、根因：為什麼模板在這裡不成立，而 H-Q 成立

模板的機制 1 要求「信號由玩家自己的合法動作產生，邊際成本接近 0」。H-Q 能這樣，是因為**三種拳在期望值上完全等價**（對一個隨機的對手，出石頭、布、剪刀的期望相同），連出同一拳什麼都不用放棄。D-6 的結構相反：

1. **每一回合只有一個動作，而每個動作都有期望值**（買低、賣高、不動各不同）。所以信號就是「別的動作」，它的成本是機會成本，量出來平均 3 到 15 現金，相對於一局照曲線打的總利潤 14 到 46 現金，是 10% 到 30%。
2. **AI 的承諾（存貨）不夠硬。** 存貨要一回合一件賣掉、來回手續費 2，但這只是 2 現金，而真正會損失的只有「預測價格與實際價格的差」，衝擊只有 1 到 4 格（共用價格下再大會出現自己抬價套利：規則 B〔每件推 2〕的來回買賣現金已經是 60.1，貼著 60 的線；`IMPACT 4` 四捨五入的版本是 68.9，大於開局的 60）。**要讓第四欄大過第二欄，衝擊要大；衝擊大，共用價格的套利就會出現，這是這張牌的規則本身的矛盾，不是參數問題。** 改成「只推對手」（規則 C）可以消除套利，衝擊可以任意大，但信號的成本也跟著變大（因為騙一次要放掉的買賣更值錢），第二欄追著第四欄跑。
3. **玩家有一條更好的路：自己也讀。** 騙（在規則 B 最好 −2.5）不如單純也讀（0），所以沒有人會去騙。這跟 H-4 同一個形狀（9.6：「騙的人輸得比不騙的多」），只是這次連「不騙」的基準線也被 AI 的建模壓低了。

**模板在這裡的作用，是在寫任何程式之前，用四欄預測「第二欄 ≈ 第四欄、風險很大」，然後用一個幾小時的原型證實。** 省下了整張牌的實作、測試與 A1 到 A5 的量測。但它**沒有**回答「模板的正面（三列表過關）在方塊也成立嗎」：D-6 在四欄這一關就被擋下，三列表沒有機會過。這一點要老實寫給老闆：**我只證明了「模板的前置檢查在方塊也有預測力」，沒有證明「照模板做出來的方塊牌好玩」。**

### 五、這個結論的邊界（我沒有做到的）

- 原型 AI 是我手寫的一步最佳反應，不是真的搜尋型加上 `Game`；真的實作的 AI 只會更粗，不會更好。但**劇本玩家的騙法只有兩種家族（連買再選擇性連賣）**，每種 20 種時機，不是窮盡。有人可能找得到我沒找到的騙法，例如利用最後幾回合「沒賣掉的貨不值錢」的懸崖，在對方必須出清的回合堵住出口（我沒有量）。
- 預測模型用預設一組參數（窗口 6／衰減 0.6／往前推 0.7）加上兩組「更容易受騙」的變體（往前推 1.0；往前推 1.0 加窗口 3、衰減 0.3；規則 A、B 各 40 場，人坐 0 號邊）：容易受騙的 AI 在 A 規則下，騙一次的平均是 −4.6 到 −5.3，對「關掉建模」是 −6.2，AI 被騙到的量約 +0.9 到 +1.6，仍然是負的；在 B 規則下容易受騙的 AI 強度只剩 +4.1 到 +5.3，而騙局依然沒有贏過基準線。AI 越容易被騙就越弱，**沒有一個設定同時讓「騙會贏」與「AI 仍然是強的」**。
- 沒有寫 `Game`，所以 4.2 的盲測、洩漏注入、`depth` 的 6 步額度、A1 到 A5 四個區塊、平均局長都沒有量。小規格那一整串「實作前要驗證的事」的第二大項沒有開始。

### 六、小規格裡發現的三個問題（將來復活這張牌時先處理）

1. **數字矛盾：** 規則說 `dev ← trunc((dev + IMPACT × net) / 2)`，`IMPACT = 2`，兩邊各買 1 件（`net = 2`）得 `trunc((0 + 4) / 2) = 2`；規則裡的例子也寫 +2，但「驗收題」第 3 點與「資訊」處寫「下一回合價格多 +4」。實際是 +2。
2. **`MIN_CHOOSE = 30` 讓搜尋型看不到結算。** 結算要「鎖定 → `locked` 等 2 tick → 開牌」，而 `locked` 要等 `choose` 過了至少 30 tick 才開始；搜尋型最深往前模擬 6 個 tick（9.5），不管等級多高，都走不到 `result`。小規格的「等級曲線從結算流程長出來（只有深度 ≥3 模擬得到）」因此不成立。要修：把最短回合時間挪到 `prep`（準備期加長），`choose` 不設下限。
3. **「都不按＝不動」會讓模擬裡的對手永遠不鎖定。** 搜尋型在模擬裡讓對手做 `actions()` 的第一個動作；如果第一個動作是「全放開」，對手在 6 個 tick 內不會鎖定，`step` 就走不到結算。H-Q 之所以走得到，是因為第一個動作是石頭（一個真的出手）。「不動」要有一個明確的鍵（例如下），而且 `actions()[0]` 不能是全放開。

  1. **改成誠實的技術牌**（H-4 的路線，9.6）：不宣稱玩家可以騙 AI。規則 B 的數字（會讀對不讀 81%、亂按 0%）就是 GOAL 第 3 條「技術有報酬、運氣沒有」的證據。需要補的是真的實作與 A1 到 A5，我沒有做，預估和 D-Q 同一個量級。
  2. **補一個免費的信號維度再重新過一次四欄**（模板的缺口，見下）。我沒有試。
- **模板的缺口（建議寫進 DESIGN-AI-FUN 10.2 機制 1）：** 機制 1 隱含「選擇集裡有幾個期望值相等的選項」（H-Q 的三拳）。**回合制市場、賽跑這類「每個動作都有期望值差」的牌沒有這種維度**，信號的成本等於機會成本。判斷方法：問「如果我在這一回合做別的動作，我會少賺多少？」少於 AI 讀錯的損失才行。在寫小規格時就能回答，不用等量測。

`ai.mjs`（市場規則加 AI），`final.mjs`（三列表與消融），以及小規格原本的五個手寫劇本在一開始的 `sim.mjs`／`run3.mjs`。以下是最關鍵的兩份。其餘（原型關卡的五個劇本）只是 `curve()`（買低賣高的規則腳本）、`roundTrip()`、`reader()`（避開對手上一回合買的貨）與 `follower()`。

```js
// ai.mjs — 規則：price_i(g) = clamp(round(base[g][r] + dev_i[g]), 2, 20)
//   dev_i[g] ← rho * dev_i[g] + u * (selfW * 我的淨買賣[g] + 對手的淨買賣[g])
//   selfW = 1：共用價格；selfW = 0：只推對手。買付 price + 1，賣得 max(1, price − 1)，最後只算現金。
function readPressure(hist, oppSide, W, DEC, oppInv) { // 對手最近 W 回合的淨買賣，每早一回合乘 DEC
  const q = [0, 0, 0]; let wt = 0; const n = hist.length;
  for (let k = 1; k <= Math.min(W, n); k++) {
    const a = hist[n - k][oppSide]; const w = Math.pow(DEC, k - 1); wt += w;
    if (a && !a.pass) q[a.good] += w * (a.side === 'buy' ? 1 : -1);
  }
  if (wt > 0) for (let g = 0; g < 3; g++) q[g] /= wt;
  for (let g = 0; g < 3; g++) if (oppInv[g] === 0 && q[g] < 0) q[g] = 0; // 沒存貨賣不出去
  return q;
}
function exitValue(inv, F, r0, R, FEE) { // 把每件存貨分配到未來不同的回合（一回合賣一件），貪心取最高價
  const cands = [];
  for (let g = 0; g < 3; g++) if (inv[g] > 0) for (let t = r0; t < R; t++) cands.push([Math.max(1, F[g][t] - FEE), g, t]);
  cands.sort((a, b) => b[0] - a[0]);
  const used = new Set(), cnt = [0, 0, 0]; let sum = 0;
  for (const [v, g, t] of cands) { if (used.has(t) || cnt[g] >= inv[g]) continue; used.add(t); cnt[g]++; sum += v; }
  return sum;
}
function forecast(base, devNow, netNow, pressure, lam, rho, u, r, R, P) { // 預測 t = r+1..R-1 的價格
  const F = [[], [], []];
  for (let g = 0; g < 3; g++) {
    let d = devNow[g], net = netNow[g]; const press = pressure ? pressure[g] : 0;
    for (let t = r + 1; t < R; t++) { d = rho * d + u * net; F[g][t] = clamp(base[g][t] + d, P); net = press * Math.pow(lam, t - r); }
  }
  return F;
}
// makeAI({ read, W = 6, DEC = 0.6, lam = 0.7 })：對每個合法動作 a，
//   價值 = 現金(我, a 之後) − 現金(對手) + exitValue(我的存貨, 我的預測價格) − exitValue(對手存貨, 對手的預測價格)
//   我的預測價格的壓力 = selfW * 我這一手 + (read ? 對手壓力 q : 0)；對手的預測價格的壓力 = 我這一手 + (read && selfW ? q : 0)
//   取價值最大的動作。read = false 就是消融。
```

## 我做的決定

1. **回合數 24（不是 60）。** 理由：見前面。每回合最短 82 tick。
2. **行情曲線公開，而且是確定的（沒有隨機驚喜）。** 理由：這張牌要玩家「讀對手」，不是「猜曲線」；曲線有隨機的話，大部分勝負來自運氣（TEST_PLAN 的 A4 與「人贏得了、不靠運氣」）。
3. **價格 = 曲線 + 雙方買賣的偏移。** 理由：老闆的要求（價格由雙方買賣推動）。偏移每回合減半，所以市場會復原，不會被推到天邊。
4. **手續費 `FEE = 1`，且 `IMPACT = 2`、衰減 1/2。** 理由：來回買賣的期望是負的（已經算過），沒有手續費會變成「買了下一回合賣」的無風險套利（偏移 +1）。
5. **兩邊在回合開頭價格成交，不分先後。** 理由：同時出手要對稱，不引入「誰先成交」的優先順序；代價是同一回合碰撞的成本由下一回合的偏移承擔。
6. **一回合只能做一件事、一件貨。** 理由：這樣每回合只有 7 個選擇，AI 的 `actions` 很小、玩家看得懂、24 回合才有節奏。
7. **最後只算現金，沒賣掉的貨是 0。** 理由：不用定義「存貨怎麼估價」（用市價估價會讓人自己把價格推高來灌水）；也讓「結束前要賣完」成為真的壓力與 `danger`。
8. **`MIN_CHOOSE = 30`。** 理由：若兩邊都很快鎖定，一局約 17 秒，低於 30 秒；有下限，最短一局 33 秒。
9. **同時按 a 與 b 當作沒動作。** 理由：避免誤觸的賣出（賣掉存貨是不可逆的）。
10. **預設性格用搜尋型，偏離方塊預設的貪心型。** 理由：見「預設性格與等級曲線」。要在實作後量過再定。
11. **畫面文字：** 貨名（穀、布、鐵）與「已鎖定」要放 `src/shell/strings.ts`；`render` 其餘只畫數字與折線。
12. **`meta`：** `defaultPolicy: 'pathfinder'`、`baseLevel: 2`、`symmetric: true`、`luckHeavy` 不標（沒有隨機）。
