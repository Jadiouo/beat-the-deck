# H-K｜紅心馬拉松

規則一句話：**帶著同一筆籌碼**連打四場縮短版的紅心牌，每場開打前兩邊**同時暗中決定要不要用掉自己唯一的「加倍牌」**；每場的勝負按賭注轉移籌碼，四場打完籌碼多的贏。

局長：四場，每場約 700 tick 加上開場決定約 200 tick，共約 3600 tick，**約 60 秒**（`config.maxTicks` 的預設 3600 就是整場的上限，見「參數」）。

♥ 紅心 K。**設計文件，尚未實作、未量測。**

類型：**互相讀取型**（加倍牌是暗中同時決定的，沒有用掉的加倍牌是公開的威脅）＋它**包著**別張牌的互動（每一場裡打的是那張牌自己的 AI）。

## 依賴哪幾張牌（重要）

H-K 只能接**已經實作**的紅心牌，因為它直接呼叫那些牌的 `init`／`step`／`actions`／`evaluate`／`winner`：

| 牌 | 狀態 | 在 H-K 裡 |
|---|---|---|
| H-A 貪心骰 | **已實作** | 第一批的場次 |
| H-2 引信 | **已實作** | 第一批的場次 |
| H-3 懸崖 | **已實作** | 第一批的場次 |
| H-Q 加碼 | **已實作** | 第一批的場次 |
| H-4 比大小 | **只有小規格，還沒實作** | 實作後加入「場次池」 |
| H-5 二十一點 | 只有小規格，還沒實作 | 同上 |
| H-6 地雷區 | 只有小規格，還沒實作 | 同上 |
| H-7 血換分 | 只有小規格，還沒實作 | 同上 |
| H-8 加倍或歸零 | 只有小規格，還沒實作 | 同上 |
| H-9 吹牛骰 | 只有小規格，還沒實作 | 同上 |
| H-10 暗標 | 只有小規格，還沒實作 | 同上 |
| H-J 三張牌撲克 | 只有小規格，還沒實作 | 同上 |

**所以 H-K 現在只能用 H-A、H-2、H-3、H-Q 四張，馬上就能做。** SPEC 說的「A 到 10 的短版」要等其他牌實作之後才完整；H-K 的 `STAGE_POOL` 是一個常數陣列，**新牌實作完成後只要在這個陣列加一行**（而且測試要確認每個進池的牌都有 `symmetric` 或明確的先後手規則）。**不要在 H-K 實作時依賴還沒存在的牌。**

## 規則

- **場次：** 四場，從 `STAGE_POOL`（現在是 `['H-A', 'H-2', 'H-3', 'H-Q']`）依**牌面由小到大**依序打；池子超過四張時，用種子抽四張再排序。
- **籌碼：** 兩邊起始 100，加起來永遠 200。
- **每場開打前（開場決定）：** 兩邊**同時**暗中選 **a：用掉加倍牌**（這一場的賭注加倍）或 **b：不用**。**每人整場只有一張加倍牌**。選了不能改。鎖定 2 tick 後公開兩邊的選擇。
  - 賭注倍數 `m = 1 + 這場用加倍牌的人數`（沒人用是 1、一個人用是 2、兩個人都用是 3，同 H-Q 決定 13）。
  - 開場決定最多等 120 tick，超時自動不用。AI 與人都有 45 tick 準備（輸入忽略）。
- **這一場打的是那張牌的縮短版：** 用那張牌自己的 `init(stageSeed, { maxTicks: STAGE_TICKS })` 開一局，每個 tick 把兩邊的輸入照原樣交給那張牌的 `step`，直到那張牌 `isOver`（它自己的規則，或到了 `STAGE_TICKS`）。贏家由那張牌的 `winner` 決定。
- **這一場的籌碼轉移：** 贏的人從輸的人拿走 `STAKE × m`（`STAKE = 10`）。平手不動。
- 四場結束後，籌碼多的贏，一樣多平手（`winner = null`）。`score` 是兩邊籌碼。
- **「前面輸了後面要冒更大的風險」是這樣來的：** 你落後 20，最後一場又用了加倍牌：贏回 20 或輸得更多；領先者知道落後者手上有加倍牌，所以會在前面把差距拉開到「對方用加倍牌也追不回」（20 以上），或自己也留著加倍牌（兩邊都用變 3 倍，更賭）。

## 參數

`STAGE_POOL`、`STAGES = 4`、`STAKE = 10`、`DOUBLERS = 1`、`BET_PREP = 45`、`BET_TIMEOUT = 120`、`LOCK_TICKS = 2`、`RESULT_TICKS = 30`。
**每場的上限由 `config.maxTicks` 算：** `STAGE_TICKS = floor((maxTicks − STAGES × (BET_PREP + BET_TIMEOUT + LOCK_TICKS + RESULT_TICKS)) / STAGES)`；`maxTicks = 3600` 時是 `(3600 − 4 × 197) / 4 = 703`。`maxTicks` 小於 `STAGES × 400` 時 `init` 丟 `RangeError`（同 C-10 的做法）。
**H-K 不改任何子遊戲的常數（H-A 的 50 分、H-Q 的 10 回合都不變），只用 `maxTicks` 縮短它們**；這些牌都遵守「到了 `maxTicks` 就結束、比目前的分數」（見各牌的小規格），所以縮短是合法的。**H-A、H-2、H-3、H-Q 在 703 tick 內大概只能打完一部分（例如 H-Q 約 5 到 6 回合、H-2 約 2 到 3 局）**，勝負以那個時間點的分數為準；這是縮短版的代價。

## 資訊限制

- 公開：場次表、兩邊籌碼、哪些場已經用了加倍牌（每人剩一張還是沒了）、每一場的結果。
- 隱藏：**開場決定那一刻對方是否用加倍牌**（`pending`）。其他隱藏資訊全部來自子遊戲（例如 H-Q 的出手與加碼），**H-K 的 `actions`／`evaluate` 把子遊戲的呼叫原樣轉過去，所以那張牌的防偷看自動繼承**，H-K 自己要加：「只有對方 `pending` 不同的開場狀態，AI 側 `evaluate`、`actions` 相等」，加上黑箱 `decide` 版本（深度 1、3、6）。
- **子遊戲的 state 完整放在 H-K 的 state 裡，所以那張牌的所有隱藏資訊（H-Q 的 `pending`、`raised`）也在 H-K 的 state 裡；H-K 不可以從子遊戲的 state 讀任何那張牌的 `evaluate` 沒讀的欄位。**

## 預設性格與 baseLevel

搜尋型（`pathfinder`）。**每一場實際用的性格就是那張牌自己的預設性格**（H-A、H-2、H-3 是賭徒型，H-Q 是搜尋型）：SPEC 7.1「J、Q、K 與鬼牌可以混用」，所以 H-K 允許。開場決定由 H-K 自己的 `evaluate` 計算，與選了什麼性格無關（見下）。`baseLevel = 4`（SPEC 7.2：K 是 4）。`symmetric: false`（H-A 的先後手不對稱，而 H-K 沒有權力改它；規則在 H-A 的小規格裡）。`luckHeavy: true`。

## 操作

開場決定：a 用加倍牌、b 不用。每一場的操作就是那張牌自己的操作（見各牌小規格）；**H-K 需要在畫面上標示現在是哪一場、操作說明跟著換。** 不新增按鍵。

## state

`HKState`：`tick`、`maxTicks`、`over`、`winner`；`stageIdx`（0 到 3）；`stages`：這場的牌 id 陣列（4 個，種子決定）；`chips`；`doublers`：`[n0, n1]`（剩幾張，各 1 或 0）；`phase`：`'bet' | 'betLocked' | 'betReveal' | 'play' | 'stageResult'`；`wait`、`idle`；`pending`：`[Move|null, Move|null]`（`bet` 階段，隱藏）；`mult`：這場的倍數（公開後才有值）；**`sub`：這場那張牌的 state（`JSON` 可序列化，完整放進來）**；`results`：已結束的場 `{ id, winner, mult, delta }`；`salt`、`rng`。

## 動作與評估

- `actions(state, side)`：`phase = 'bet'`、還沒選：`[b 不用, a 用]`（沒有加倍牌時只有 b）；`phase = 'play'`：**直接回傳那張牌的 `actions(sub, side)`**；其他 `[全放開]`。
- `evaluate(state, side)`：
  - 結束：`gain = 籌碼差 ± 1000`。
  - `bet`、`betLocked`：`gain = 籌碼差 + HABIT · [我選不用]`，`HABIT = 0.01`。**反射規則：除了最後一場，不用加倍牌。** 一個保守、可預測的 AI：它把牌留到最後。
  - `betReveal`、`play`：`gain = 籌碼差 + E_轉移 + 0.001 · 子遊戲的 gain`。`E_轉移 = Σ_(場次 j 剩餘) P(我贏 j) · STAKE · m_j`（`m_j` 的未知部分用對手模型），其中 `P(我贏 j)` 用 `edge[j]`（一張表，每張牌一個數字，**第一版先全放 0.5，實作後用 A1 到 A4 的量測填**，例如 H-Q 對人類模型這個玩家的實測勝率）加上**子遊戲當下的領先程度**（`play` 階段，用該牌 `evaluate` 的 `gain` 轉成一個小的勝率調整，每一場最多 ±0.2）。
  - 對手用不用加倍牌的模型：領先者較不用，落後者較用；**只讀公開資訊**（`chips`、`doublers`、`results`）。
  - `danger`：這一場輸掉的 `STAKE × m` 占剩餘籌碼的比例，上限 1。

## 結算流程與等級曲線（準則 5.1）

**開場決定 3 步：** 選（`betLocked`，`wait = 2`）→ 鎖定第二步 → 公開倍數並進入 `betReveal`（`wait = 30`，倍數在 state 裡但 `evaluate` 對對方的選擇用模型、不讀 `pending`／`mult` 以外的東西）→ 進 `play`。
- **深度 1 到 2（等級 1 到 3）：** 走不到 `betReveal`，只剩反射規則：**加倍牌留到最後一場**（它是一個看得出來的習慣：「它的加倍牌一直沒用，最後一場要小心」；你可以在最後一場前把領先拉到 ≥ 20 + 讓它的加倍牌失效）。
- **深度 ≥ 3（等級 4 以上）：** 走得到 `betReveal`，`evaluate` 用 `E_轉移` 與對手模型選擇**在對自己最強的那一場**用（例如它在 H-Q 有優勢就在 H-Q 用），**落後時提早用、領先時留著當威脅**。
- **等級 10：** 加上快速反應、每 tick 重新決定；**每一場的子遊戲仍然是那張牌自己的等級曲線**（H-K 的全域等級與每張牌的 `baseLevel` 一起決定實際等級，同 SPEC 7.2）。
- 子遊戲裡的步數、`depth` 的意義**完全由那張牌決定**（例如 H-Q 要 3 步），H-K 只是把 `step` 原樣轉過去，不加一個 tick 的延遲，所以子遊戲的等級曲線不被破壞。

## 為什麼跟 AI 互動起來好玩

**AI 的哪一個選擇會改變你的最好做法？** **它有沒有用掉加倍牌。** 它還留著：最後一場你不能只領先 10。它第二場就用了：後面它沒有後路，你可以在第四場放心。**它在哪一場用：** 它選在 H-Q 用，是因為它在 H-Q 比你強。

**你怎麼騙它：** 第一場故意不全力（輸 10），讓它覺得你落後、不會用加倍牌（落後者較用），它就把自己的加倍牌留著；其實你領先的是你自己早就計畫好的最後一場。或反過來：在你強的那一場**用加倍牌**，讓它的模型以為你是落後者而亂跟。

**四種性格（每場的子遊戲照那張牌自己的性格不變，這裡只談開場決定）：**

| 性格 | 開場決定怎麼打 | 利用它 |
|---|---|---|
| 搜尋型 | `E_轉移` 與對手模型；落後時用、領先時留 | 騙它（見上） |
| 精準型 | 只在「勝率 ≥ 0.6 的一場」用；從不在輸面用 | 它的加倍牌是個可靠的訊號：它用了就是它認為強的那一場，你要小心 |
| 貪心型 | 一步看：第一個勝率 > 0.5 的場就用 | 很早就用掉了；後面幾場它沒有加倍牌，你可以安心領先 |
| 賭徒型 | 落後越多越早用加倍牌，越早用越賭 | 領先時你不用管它；它落後時第二場就用，所以那一場要贏 |

## 我做的決定

1. **「縮短版」靠 `maxTicks`，不改子遊戲的常數。** 理由：CLAUDE.md 第 4 條，H-K 不能改別張牌；這些牌的 `step` 都支援 `maxTicks` 結束，所以是合法的縮短。**代價：縮短的方式很粗**（例如 H-2 只打 2、3 局）；若指揮官要更精緻的縮短（參數化回合數），要先改那些牌的介面，這是一個要另外提的 PR，不在這裡擅自做。
2. **同一筆籌碼，每場賭注 10、加倍牌一張。** 理由：「前面輸了後面要冒更大的風險」要有一個可以冒大的選擇，而加倍牌是最簡單、最有戲劇的那個（H-Q 的加碼是同一類手法）。籌碼 100 與賭注 10：四場最多轉移 `10 × 3 × 4` ，不會有人破產，最終勝負由多場決定。
3. **開場決定用 `pending`。** 理由：DESIGN 4.3；同時暗中決定，才有「它留著加倍牌嗎」的猜。
4. **場次由小到大、池子大於四張時種子抽四張。** 理由：「A 到 K 的馬拉松」要有進化的感覺；固定四張時重播相同。
5. **賭注倍數 `1 + 人數`，兩邊都用是 3 倍。** 理由：同 H-Q。
6. **子遊戲的勝負照那張牌的 `winner`，不另外算分差。** 理由：每張牌的分數單位不同（H-A 的總分、H-2 的總分、H-Q 的籌碼），硬轉成統一的分差要發明規則；用勝負最簡單。
7. **`edge` 表第一版全放 0.5。** 理由：我沒有量過任何一張牌 AI 對人的真實勝率，不能自己編。實作者在 A1 到 A4 量測之後再填。
8. **`symmetric: false`。** 理由：H-A 的先後手不對稱，H-K 不能擅自改它。

## 實作時要量的東西（未量測）

- A1 到 A5：**A5 要小心**：`evaluate` 的 `E_轉移` 與子遊戲的 `evaluate` 都要算，等級 10 的 `decide` 平均要 < 1 毫秒。
- A4：人類模型在四場裡各自的表現已經是那張牌的 A4（H-Q 約 1% 到 3.5%，H-A、H-2、H-3 是賭徒型的 A4），組合起來 **預期很低**；A4 在這張牌上**沒有鑑別力**，要在小規格寫明，改用劇本玩家：永遠不用加倍牌、永遠第一場就用、「領先時留著、落後時最後一場用」。
- 開場決定的 4.2-b 黑箱（只有對方 `pending` 不同）與注入洩漏。
- 子遊戲相容性測試：每個進池的牌，用 H-K 包起來跑與直接跑，同樣的種子與輸入得到同樣的子遊戲 state（證明 H-K 沒有改動子遊戲）。
- **實際局長：** 實測四場總 tick，目標 3300 到 3600；超過就降 `STAGE_TICKS` 或把場次降到三場。

## 我的疑慮

1. **H-K 的新互動只有「加倍牌」一個選擇、每場一次，整場 4 次決定**；我認為它比其他花色的馬拉松有深度（同一筆籌碼讓前面的結果改變後面的風險），但不是這九張裡最好玩的。真正的樂趣一半來自被它包著的那些牌。
2. **縮短版的粗糙**：H-2、H-3 只打兩三局，運氣比重高；這會讓 H-K 的勝負比單張牌更偏運氣。若實測 A1 太低，改成「每場只能用 `maxTicks` 縮短的牌」之外，要另外提 PR 讓那些牌開放「回合數」的參數。
3. **依賴風險：** H-K 是第一張依賴別張牌內部介面的牌；若 H-A 等牌之後改了 `step` 的行為，H-K 的相容性測試會紅；這是設計上的耦合，要在 PR 說明提出。
