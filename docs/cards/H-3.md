# H-3｜懸崖

♥ 紅心 3。比 H-2 多了：兩邊往懸崖衝，停得離邊緣近的得分高，掉下去就 0 分。
規則的出處是 SPEC 第 10 節「紅心共同設定」與「H-3 懸崖」。這份小規格補 SPEC 沒寫到的細節，特別是**煞車距離的解析式**。
和 H-2 一樣是「兩邊同時玩、共 5 局」，所以局的流程（兩邊都結束才停頓、停頓後進下一局）與 H-2 相同，共用的常數與畫圖小工具在 `src/games/_hearts/`。

## 規則（SPEC 第 10 節，原樣）

- 共 5 局。跑道長 300 像素，懸崖在右端。
- 兩邊同時從 0 出發，自動以每 tick 1 像素前進，速度每 30 tick 增加 0.1。按下 a 開始煞車：以每 tick 0.05 的減速度減速到停。
- 停下來的位置沒超過 300：這一局的得分是位置的整數部分。超過 300：掉下去，這一局 0 分。
- 每一局的跑道長度相同；為了不讓人背起來，每局的起始速度從 0.8 到 1.2 之間隨機，兩邊相同。
- 5 局總分高的贏。

## 參數

沒有牌自己的參數。常數：`TRACK = 300` 像素、`DECEL = 0.05`、`SPEED_STEP = 0.1`、`SPEED_EVERY = 30`、起始速度 0.8 到 1.2（`V0_MIN`、`V0_MAX`）、`ROUNDS = 5`、`ROUND_PAUSE = 45`。
**內部一律用整數的「千分之一像素」**（1 像素 = 1000）：速度 800 到 1200、每 30 tick 加 100、減速度 50、跑道 300000。
這樣「剛好 300.0」、「287.6」這種邊界不會被浮點誤差弄糊塗（0.1 與 0.05 在二進位浮點數裡都不是精確的）。`config.maxTicks` 是時間上限（預設 3600）。

## 資訊限制

沒有。位置、速度、起始速度都是公開的（畫面直接畫出來）；AI 看到的和人一樣。

## 預設性格

賭徒型（`gambler`，SPEC 7.1：紅心的預設），`baseLevel = 1`。
`symmetric = true`：兩邊的規則、起始速度、跑道完全一樣，K12 會跑。標 `luckHeavy: true`。不標 `winnerNotByScore`。不標 `seedIndependent`（每局的起始速度由種子決定）。

## 操作

按下 a（Z、X 或空白鍵）開始煞車。按下之後放開或再按都沒有作用。

## 煞車距離的解析式

設按下 a 的那個 tick 開始時速度是 `v`（像素／tick），減速度 `a = 0.05`。每個 tick 的順序是「先用目前的速度走一步，再改速度」：
按下的那個 tick 用 `v` 走一步，之後速度變成 `v − a`、`v − 2a`、……，減到 0 為止。所以煞車的距離是

```
D(v) = v + (v − a) + (v − 2a) + …（到速度 ≤ 0 為止）
     = (n + 1)·v − a·n·(n + 1)/2       其中 n = floor(v / a)
```

（`v = 1.0` 時 `n = 20`，`D = 21 − 0.05·210 = 10.5`。）連續近似：`D(v) ≈ v²/(2a) + v/2`，與精確值差 `r(a − r)/(2a)` 以內
（`r = v mod a`，最多約 0.00625 像素）；只取 `v²/(2a)` 則差 `v/2`（`v ≤ 1.2` 時不到 0.6 像素）。
`logic.ts` 匯出 `brakeDistance(speed)`（精確的離散公式，整數運算）；測試對 5 個起始速度（還有幾個除不盡的）把它和逐 tick 的模擬對照，
誤差是 0；連續近似的兩個版本也各自驗證小於 1 像素。

停下來的位置 = 按下那個 tick 開始時的位置 + `D(按下時的速度)`。AI 的 `evaluate` 用的就是這個式子。

## state

`H3State`（見 `H-3/logic.ts`）：

- `tick`、`maxTicks`、`over`、`winner`。
- `round`、`phase`（`'run'` 或 `'pause'`）、`roundTick`、`pause`：同 H-2。
- `v0`：這一局的起始速度（千分之一像素／tick，800 到 1200），兩邊相同。
- `runners`：兩邊各 `{ status, pos, speed, age }`。`status` 是 `'running'`（自動前進）、`'braking'`、`'stopped'`、`'fallen'`；
  `pos` 位置（千分之一像素）；`speed` 速度；`age` 已經跑了幾個 tick（每 30 個 tick 加速一次用）。
- `totals`、`roundScores`（兩邊各局的得分，畫面用）。
- `rng`：起始速度的 `RngState`（`rngStateFor(seed, 'v0')` 起頭）；每一局開始時抽一次。

## 動作與評估

- `actions(state, side)`：`running` 時 `[全放開, a]`（全放開排第一）；否則只有 `[全放開]`。
- `evaluate(state, side)`（只看公開資訊）：
  - 這個人這一局現在的價值 `V`：`stopped` 是得分；`fallen` 是 0；`braking` 是「照目前速度煞到停」的得分（停的位置超過 300 就是 0）；
    `running` 是「再跑 `DELAY = 16` 個 tick 才開始煞車」的得分（`DELAY` 是假設的反應延遲；停的位置超過 300 就是 0）。
  - `gain = (我的總分 + 我的 V) − (對方的總分 + 對方的 V)`。已經結束的局：`gain = 分差 ± 1000000`。
  - `danger`（0 到 1）：`braking` 時，如果會掉下去就是 1，否則 0；`running` 時是「按現在的速度，離『必須煞車』還有多少 tick」換成的緊迫度：
    `clamp(1 − 剩餘 tick / 30, 0, 1)`，剩餘 tick = （跑道 − 現在開始煞車的停點）／速度；其他狀態 0。
  - 一步看的性格往前模擬「按 a」或「全放開」：按 a 得到 `braking`（`V` 是真的停點的得分），不按得到「再跑一個 tick」的 `running`（`V` 是再延遲 `DELAY` 的得分）。
    只要再等會掉下去（`V = 0`），賭徒型領先時就煞車；落後很多時 `danger` 的加成讓它賭一把再等。

## 畫面

背景；兩條橫的跑道（人在上、AI 在下），右端是懸崖（跑道末端的暗紅色區域）；每個跑者是一個方塊，位置是 `pos / 300000` 的比例；
`braking` 時方塊後面拖一條尾巴，`stopped` 時方塊亮色並在上方畫分數，`fallen` 時方塊掉到跑道下方（暗紅色）；
上方兩邊的總分、局數的 5 個點、目前速度的一條細條。只用色盤裡的顏色，全部在 320×240 之內，沒有文字。

## maxTicks 與最壞情況

一局最長：沒有人煞車時，起始速度最慢（0.8）掉下去要 256 個 tick；有人最晚煞車、停得最晚的組合，用窮舉（起始速度 800 到 1200 每個整數、按下的 tick 0 到 300）找到的最壞是 **270 個 tick**（起始速度 801、第 239 個 tick 按下）。
5 局最壞 5 × 270 + 4 × 45（前 4 局之後的停頓）= **1530 tick**，遠低於 `maxTicks = 3600`，所以 K5 不靠時間上限也成立。
`step` 仍然在第 `maxTicks` 個 tick 後把 `over` 設成 true（時間上限，比總分，還在跑或煞車中的不算分）。

## 我做的決定

SPEC 與 TEST_PLAN 沒有寫，這裡補上：

1. **單位。** 內部一律整數的千分之一像素（見「參數」）。起始速度 `v0 = 800 + intFrom(rng, 401)`：0.800 到 1.200 之間均勻的 401 個值（含兩端）。
2. **每個 tick 的順序。** 一個 `running` 或 `braking` 的跑者：
   ① 如果是 `running` 而且這個 tick 按了 a → 變成 `braking`（這個 tick 就用目前的速度走完，之後才開始減速，見「煞車距離」）；
   ② `pos += speed`；
   ③ 改速度：`braking` → `speed = max(0, speed − 50)`；`running` → `age += 1`，`age` 是 30 的倍數時 `speed += 100`；
   ④ 如果 `pos > 300000` → `fallen`（得 0 分，不管是不是在煞車中：煞車中衝過邊緣也是掉下去）；否則如果 `braking` 而且 `speed = 0` → `stopped`，得 `floor(pos / 1000)`。
3. **邊界：剛好 300.0。** `pos = 300000` 沒有超過，不算掉下去：停在剛好 300.0 得 300 分；`pos = 300001`（超過 0.001 像素）就掉下去 0 分。
   跑著經過 300.0 沒煞車也只有 `pos > 300000` 的那個 tick 才掉。287.6 得 287（取整數部分，不四捨五入）。
4. **速度每 30 tick 加 0.1 只對「還在跑」的跑者。** 煞車之後速度只會減。
5. **掉下去、停下來的跑者**不再動，之後的輸入都沒有作用（`stopped`、`fallen` 不會回到別的狀態）。
6. **兩邊的流程與 H-2 一樣。** 一邊結束、另一邊還在跑：這一局還沒結束；兩邊都結束：記下這一局的得分，不是最後一局就停頓 `ROUND_PAUSE`（45）個 tick（輸入被忽略）再進下一局（新的起始速度、兩邊從 0 重新出發）；最後一局結束直接 `over`。
   得分在跑者結束的那個 tick 就加進總分。
7. **時間上限、`isOver` 之後 `step`、`winner`** 與 H-2 相同（比總分、同分平手、結束後 `step` 原樣回傳）。
8. **`evaluate` 的常數。** `DELAY = 16`（假設的反應延遲，tick）與 `danger` 的 30 是調出來的，只調 `evaluate`，沒有動門檻（見 PR 說明的數字）。
   `DELAY` 比等級 5 的平均延遲（反應 11 加決定間隔平均 3，約 14）略大，但等級的延遲是整數且有抖動：把亂選關掉（epsilon = 0）、起始速度 0.8 到 1.2 每 0.01 一個（41 個）各跑一局，
   等級 10 與 9 全部停得下來（平均停在 278 與 283），等級 5 約 68% 停得下來（掉下去 13／41，停得下來時平均停在 295.5，很貼邊緣），等級 1、2 幾乎都掉下去（延遲 24、21 比 `DELAY` 大很多）。
   實際對局裡等級 1、2 多半是被亂選（提早煞車）打斷，所以得分不是 0。`evaluate` 不知道等級，這是故意的。
9. **`makeState(overrides)`。** 匯出在 `logic.ts`（測試輔助）：從「第 1 局、起始速度 1.0、兩邊在 0 以速度 1.0 跑、總分 0」的預設局面出發，用 overrides 覆蓋；`runners` 要給完整的兩邊。
10. **`meta`。** `defaultPolicy: 'gambler'`、`baseLevel: 1`、`symmetric: true`、`luckHeavy: true`。
