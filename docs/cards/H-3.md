# H-3｜懸崖

♥ 紅心 3。比 H-2 多了：兩邊往懸崖衝，停得離邊緣近的得分高，掉下去就 0 分。
規則的出處是 SPEC 第 10 節「紅心共同設定」與「H-3 懸崖」。這份小規格補 SPEC 沒寫到的細節，特別是**煞車距離的解析式**。
和 H-2 一樣是「兩邊同時玩、共 5 局」，所以局的流程（兩邊都結束才停頓、停頓後進下一局）與 H-2 相同，共用的常數與畫圖小工具在 `src/games/_hearts/`。

## 規則（SPEC 第 10 節，原樣）

- 共 5 局。跑道長 300 像素，懸崖在右端。
- 兩邊同時從 0 出發，自動以每 tick 1 像素前進，速度每 30 tick 增加 0.1。按下 a 開始煞車：以每 tick 0.05 的減速度減速到停。
- 停下來的位置沒超過 300：這一局的得分是位置的整數部分。超過 300：掉下去，這一局 0 分。
- 每一局的跑道長度相同；為了不讓人背起來，每局的起始速度從 0.8 到 1.2 之間隨機，兩邊相同。
- 5 局總分高的贏。

## 參數

沒有牌自己的參數。常數：`TRACK = 300` 像素、`DECEL = 0.05`、`SPEED_STEP = 0.1`、`SPEED_EVERY = 30`、起始速度 0.8 到 1.2（`V0_MIN`、`V0_MAX`）、`ROUNDS = 5`、`ROUND_PAUSE = 45`。
**內部一律用整數的「千分之一像素」**（1 像素 = 1000）：速度 800 到 1200、每 30 tick 加 100、減速度 50、跑道 300000。
這樣「剛好 300.0」、「287.6」這種邊界不會被浮點誤差弄糊塗（0.1 與 0.05 在二進位浮點數裡都不是精確的）。`config.maxTicks` 是時間上限（預設 3600）。

## 資訊限制

沒有。位置、速度、起始速度都是公開的（畫面直接畫出來）；AI 看到的和人一樣。

## 預設性格

賭徒型（`gambler`，SPEC 7.1：紅心的預設），`baseLevel = 1`。
`symmetric = true`：兩邊的規則、起始速度、跑道完全一樣，K12 會跑。標 `luckHeavy: true`。不標 `winnerNotByScore`。不標 `seedIndependent`（每局的起始速度由種子決定）。

## 操作

按下 a（Z、X 或空白鍵）開始煞車。按下之後放開或再按都沒有作用。

## 煞車距離的解析式

設按下 a 的那個 tick 開始時速度是 `v`（像素／tick），減速度 `a = 0.05`。每個 tick 的順序是「先用目前的速度走一步，再改速度」：
按下的那個 tick 用 `v` 走一步，之後速度變成 `v − a`、`v − 2a`、……，減到 0 為止。所以煞車的距離是

```
D(v) = v + (v − a) + (v − 2a) + …（到速度 ≤ 0 為止）
     = (n + 1)·v − a·n·(n + 1)/2       其中 n = floor(v / a)
```

（`v = 1.0` 時 `n = 20`，`D = 21 − 0.05·210 = 10.5`。）連續近似：`D(v) ≈ v²/(2a) + v/2`，與精確值差 `r(a − r)/(2a)` 以內
（`r = v mod a`，最多約 0.00625 像素）；只取 `v²/(2a)` 則差 `v/2`（`v ≤ 1.2` 時不到 0.6 像素）。
`logic.ts` 匯出 `brakeDistance(speed)`（精確的離散公式，整數運算）；測試對 5 個起始速度（還有幾個除不盡的）把它和逐 tick 的模擬對照，
誤差是 0；連續近似的兩個版本也各自驗證小於 1 像素。

停下來的位置 = 按下那個 tick 開始時的位置 + `D(按下時的速度)`。AI 的 `evaluate` 用的就是這個式子。

## state

`H3State`（見 `H-3/logic.ts`）：

- `tick`、`maxTicks`、`over`、`winner`。
- `round`、`phase`（`'run'` 或 `'pause'`）、`roundTick`、`pause`：同 H-2。
- `v0`：這一局的起始速度（千分之一像素／tick，800 到 1200），兩邊相同。
- `runners`：兩邊各 `{ status, pos, speed, age }`。`status` 是 `'running'`（自動前進）、`'braking'`、`'stopped'`、`'fallen'`；
  `pos` 位置（千分之一像素）；`speed` 速度；`age` 已經跑了幾個 tick（每 30 個 tick 加速一次用）。
- `totals`、`roundScores`（兩邊各局的得分，畫面用）。
- `rng`：起始速度的 `RngState`（`rngStateFor(seed, 'v0')` 起頭）；每一局開始時抽一次。

## 動作與評估

- `actions(state, side)`：`running` 時 `[全放開, a]`（全放開排第一）；否則只有 `[全放開]`。
- `evaluate(state, side)`（只看公開資訊）：
  - 這個人這一局現在的價值 `V`：`stopped` 是得分；`fallen` 是 0；`braking` 是「照目前速度煞到停」的得分（停的位置超過 300 就是 0）；
    `running` 是「再跑 `DELAY = 16` 個 tick 才開始煞車」的得分（`DELAY` 是假設的反應延遲；停的位置超過 300 就是 0）。
  - `gain = (我的總分 + 我的 V) − (對方的總分 + 對方的 V)`。已經結束的局：`gain = 分差 ± 1000000`。
  - `danger`（0 到 1）：`braking` 時，如果會掉下去就是 1，否則 0；`running` 時是「按現在的速度，離『必須煞車』還有多少 tick」換成的緊迫度：
    `clamp(1 − 剩餘 tick / 30, 0, 1)`，剩餘 tick = （跑道 − 現在開始煞車的停點）／速度；其他狀態 0。
  - 一步看的性格往前模擬「按 a」或「全放開」：按 a 得到 `braking`（`V` 是真的停點的得分），不按得到「再跑一個 tick」的 `running`（`V` 是再延遲 `DELAY` 的得分）。
    只要再等會掉下去（`V = 0`），賭徒型領先時就煞車；落後很多時 `danger` 的加成讓它賭一把再等。

## 畫面

背景；兩條橫的跑道（人在上、AI 在下），右端是懸崖（跑道末端的暗紅色區域）；每個跑者是一個方塊，位置是 `pos / 300000` 的比例；
`braking` 時方塊後面拖一條尾巴，`stopped` 時方塊亮色並在上方畫分數，`fallen` 時方塊掉到跑道下方（暗紅色）；
上方兩邊的總分、局數的 5 個點、目前速度的一條細條。只用色盤裡的顏色，全部在 320×240 之內，沒有文字。

## maxTicks 與最壞情況

一局最長：沒有人煞車時，起始速度最慢（0.8）掉下去要 256 個 tick；有人最晚煞車、停得最晚的組合，用窮舉（起始速度 800 到 1200 每個整數、按下的 tick 0 到 300）找到的最壞是 **270 個 tick**（起始速度 801、第 239 個 tick 按下）。
5 局最壞 5 × 270 + 4 × 45（前 4 局之後的停頓）= **1530 tick**，遠低於 `maxTicks = 3600`，所以 K5 不靠時間上限也成立。
`step` 仍然在第 `maxTicks` 個 tick 後把 `over` 設成 true（時間上限，比總分，還在跑或煞車中的不算分）。

## 我做的決定

SPEC 與 TEST_PLAN 沒有寫，這裡補上：

1. **單位。** 內部一律整數的千分之一像素（見「參數」）。起始速度 `v0 = 800 + intFrom(rng, 401)`：0.800 到 1.200 之間均勻的 401 個值（含兩端）。
2. **每個 tick 的順序。** 一個 `running` 或 `braking` 的跑者：
   ① 如果是 `running` 而且這個 tick 按了 a → 變成 `braking`（這個 tick 就用目前的速度走完，之後才開始減速，見「煞車距離」）；
   ② `pos += speed`；
   ③ 改速度：`braking` → `speed = max(0, speed − 50)`；`running` → `age += 1`，`age` 是 30 的倍數時 `speed += 100`；
   ④ 如果 `pos > 300000` → `fallen`（得 0 分，不管是不是在煞車中：煞車中衝過邊緣也是掉下去）；否則如果 `braking` 而且 `speed = 0` → `stopped`，得 `floor(pos / 1000)`。
3. **邊界：剛好 300.0。** `pos = 300000` 沒有超過，不算掉下去：停在剛好 300.0 得 300 分；`pos = 300001`（超過 0.001 像素）就掉下去 0 分。
   跑著經過 300.0 沒煞車也只有 `pos > 300000` 的那個 tick 才掉。287.6 得 287（取整數部分，不四捨五入）。
4. **速度每 30 tick 加 0.1 只對「還在跑」的跑者。** 煞車之後速度只會減。
5. **掉下去、停下來的跑者**不再動，之後的輸入都沒有作用（`stopped`、`fallen` 不會回到別的狀態）。
6. **兩邊的流程與 H-2 一樣。** 一邊結束、另一邊還在跑：這一局還沒結束；兩邊都結束：記下這一局的得分，不是最後一局就停頓 `ROUND_PAUSE`（45）個 tick（輸入被忽略）再進下一局（新的起始速度、兩邊從 0 重新出發）；最後一局結束直接 `over`。
   得分在跑者結束的那個 tick 就加進總分。
7. **時間上限、`isOver` 之後 `step`、`winner`** 與 H-2 相同（比總分、同分平手、結束後 `step` 原樣回傳）。
8. **`evaluate` 的常數。** `DELAY = 16`（假設的反應延遲，tick）與 `danger` 的 30 是調出來的，只調 `evaluate`，沒有動門檻（見 PR 說明的數字）。
   `DELAY` 比等級 5 的平均延遲（反應 11 加決定間隔平均 3，約 14）略大，但等級的延遲是整數且有抖動：把亂選關掉（epsilon = 0）、起始速度 0.8 到 1.2 每 0.01 一個（41 個）各跑一局，
   等級 10 與 9 全部停得下來（平均停在 278 與 283），等級 5 約 68% 停得下來（掉下去 13／41，停得下來時平均停在 295.5，很貼邊緣），等級 1、2 幾乎都掉下去（延遲 24、21 比 `DELAY` 大很多）。
   實際對局裡等級 1、2 多半是被亂選（提早煞車）打斷，所以得分不是 0。`evaluate` 不知道等級，這是故意的。
9. **`makeState(overrides)`。** 匯出在 `logic.ts`（測試輔助）：從「第 1 局、起始速度 1.0、兩邊在 0 以速度 1.0 跑、總分 0」的預設局面出發，用 overrides 覆蓋；`runners` 要給完整的兩邊。
10. **`meta`。** `defaultPolicy: 'gambler'`、`baseLevel: 1`、`symmetric: true`、`luckHeavy: true`。


## 探針 A（完整版）：玩家讀 AI 有沒有用（2026-10-21；**定義在量之前固定**，DESIGN-AI-FUN 10.35、10.54、10.59、10.61、10.64、10.70、10.73）

**為什麼量。** 結構篩檢（`docs/PROBE-A-TRIAGE.md` 4.2）量的是「擾動對手狀態時 AI 的動作會不會變」：H-3 的改變率是 **精準型 0.0%、搜尋型 0.0%、貪心型 0.0%、賭徒型 3.0%**（預設性格欄 ＝ 賭徒型 ＝ 3.0%；判定 `grey`，原樣照抄；放寬欄是 `-`）。10.66 證明改變率只是必要條件、不能當互動強度的排序。這張牌在 4.3 屬「未知」，不是零。這一節量「玩家讀 AI」（必要條件 2）。**`meta.ts` 的 `defaultPolicy` 確實是 `gambler`**（已核對）。

**這張牌能互動的地方很少：** 兩邊各跑各的跑道，位置、速度、起始速度全是公開的，而且**沒有任何東西是隱藏的或隨機的**（起始速度兩邊相同、畫面直接畫出來）。對手能影響我的只有兩樣：（一）我的總分與它的總分之差（一局 5 局的勝負是比總分）；（二）它這一局已經結束的結果（停在哪、有沒有掉下去）。所以 (c) 能讀的有用東西只有「總分差」與「對手這一局的結果」，用在「我要煞得多緊」上。

**量測前就寫下的結構預測（不是量出來的，是從規則推的）：** 煞車距離是確定的解析式（`brakeDistance`），沒有任何不確定性時，「在再等一個 tick 就會停過邊緣的最後一刻煞車」（`b-exact-0`）每一局都停在 299 到 300，這是**每一局能拿到的幾乎最高分**，而且不會掉下去。對手的任何狀態都不能讓它更好，因為沒有風險可以取捨。所以**在玩家的手永遠準的格子，任何讀對手的成員都不可能超過 `b-exact-0`**：我預測 (c)−(b\*) ≤ 0（勝率差是 0，分差是 0 或負），而且這是結構性的，不是這個 AI 的性質。**要讓讀對手有機會有用，玩家的執行得有不確定性**（手不準，掉下去的風險才是取捨，這時落後多敢、領先多保守才有意義）。這是我加的**敏感度分析**，不是 SPEC：`jitter ＝ J` 表示玩家煞車的按鍵要晚 0 到 J 個 tick 才真的落下（每局抽一次，均勻；抽自 `rngStateFor(種子, 'jitter')`，(b)(c) 同一個種子吃同一串抖動），J ＝ 5 對應人類模型每 6 個 tick 才換一次動作（SPEC 7.3）。主格是 J ＝ 0；抖動格另外報、不混。

**不改規則、不改 `logic.ts`。** 量測工具在 `probe-a.members.test-helpers.ts`（兩族，**不准碰 AI**）與 `probe-a.test-helpers.ts`（對局接線與抖動），工具測試在 `probe-a.test.ts`，大場次在 `measure.test.ts`（環境變數 `H3_PROBE_*`，檔頭有說明，heavy project）。共用工具是 `tests/ai/probe-a.shared.ts`（`compareBC`、`divergence`），沒有另寫影子控制器。

- 所以主格在「勝率」上動態範圍是退化的（(b) 範圍很寬，但那是成員之間的差別，不是格子的刻度）；分差範圍很寬（−1365 到 +126），**分差有刻度**。
- 賭徒型 L5 以下（含 L1）AI 自己很差（`d` 鏡像：AI 引擎當玩家 100%）；精準型 L10 的 (b\*) 也貼 100%。**每一格 (b\*) 都在勝率天花板**，這是衡量標準 3 的問題（見支配策略檢查），分開報。
- 抖動格（J ＝ 5、10）：(b) 最強的成員從 `exact-0` 變成 `exact-16`、`exact-24`（要留邊距才不會掉下去），**取捨出現了**，分差跟著降到 +71、+53；這才是 (c) 有機會改進的地方。
- 延遲 0 與延遲 12 的 (b) 完全相同（不讀對手的成員與延遲無關）。

**規則（量之前固定）：**
- **主格 ＝ 賭徒型 L10、玩家延遲 12、抖動 0。** 理由：(1) 賭徒型是 `meta.ts` 的預設性格；(2) L10 是遊戲最後遇到、最強的一格；(3) 延遲 12 是 AI 自己所在的那條線；(4) 結構篩檢賭徒型 3.0%（只有這一個性格不是 0）。**預先承認的限制：**(b\*) 貼 100%，只讀分差；且有上面的結構預測。
- **副格（同樣嚴格地量，不合併）：** 賭徒型 L10 延遲 0、賭徒型 L9／L7／L5 延遲 12、精準型 L10 延遲 12；**抖動敏感度格：**賭徒型 L10 延遲 12 抖動 5、抖動 10，賭徒型 L7 與 L5 延遲 12 抖動 5，精準型 L10 延遲 12 抖動 5。
- **座位（0 號邊／1 號邊）與格子分開報，不合併**（10.61 第三個陷阱）。
- 訓練種子 1000..1399（400 場，該格）；量測種子 5000..5999（1000 場，邊輪流，和局半場，同種子配對）；掃描種子 7000..7063；支配策略檢查種子 9000..9099。**四批互不重疊。**副格的場數縮成訓練 200、量測 400（D-3 的標準）。

### 二、(b) 族：不讀對手的任何東西（12 個成員）

每一局只有一個決定：什麼時候煞車。成員只准讀：自己的跑者、局數、自己的總分、`phase`；**不准讀**對手的跑者與總分。

| 名稱 | 做法 |
|---|---|
| `b-exact-M`，M ∈ {0, 4, 8, 16, 24, 32, 48} | 知道煞車距離的解析式（`brakeDistance`），在「再等一個 tick 就會讓煞車的停點超過 300 − M 像素」的最後一刻煞車。M ＝ 0 ＝ 精確煞在邊緣 |

### 三、(c) 族：讀對手公開的東西（22 個成員）

(c) 的基底與對應的 (b) 完全相同。成員**可以讀對手的公開 state**（跑者的狀態與位置、總分）。**沒有 import `evaluate`、`opponentAction`、`levelController`、`policyByName`、各性格檔，也沒有拿 AI 的控制器當成員**（`probe-a.test.ts` 掃 `probe-a.members.test-helpers.ts` 的程式碼擋這件事；`predictOpponent` 這個函數在 repo 裡不存在，派工單寫它是錯的；**真正要禁的是 `src/ai/policies/shared.ts` 的 `opponentAction`**）；**(c) 不是 AI 自己的引擎或它的鏡像**（10.61 第二個陷阱）。

| 讀法 | 命名 | 做法 |
|---|---|---|
| 讀總分差 | `c-<基底>-lead` | 總分差 ＝ 我 − 對手。領先 100 以上就更保險（`exact` 邊距加 24 像素；`pos` 早 15 像素）；落後 100 以上就更敢（`exact` 邊距減 16 像素、不低於 0；`pos` 晚 15 像素）；其餘照基底 |
| 讀對手這一局的結果 | `c-<基底>-last` | 只在最後一局、對手這一局的結果已經決定時讀（停下、掉下去、或**正在煞車**：煞車中的結果由煞車距離決定，畫面上看得到它的位置與速度，照它會停的位置算；見「定義修訂」）：這一局結束時的總分差 > 0（領先）就更保險；落後超過 300（這一局拿滿也追不上）就孤注一擲（邊距減 16、不低於 0）；其餘照基底 |

**雙胞胎（量之前固定）：**每個 (b)（`b-never` 除外）都有 `-lead` 與 `-last` 兩個 (c) 雙胞胎（共 22 對），機器一模一樣、只差讀什麼，**所以不論訓練種子上誰是 (b\*)，它都有對應的 (c) 版本**（10.68 第六小節）。`probe-a.test.ts` 有一條測試：沒有東西可讀（第 1 局、總分相同、對手還在跑）時每一對逐 tick 按鍵相同；另有測試證明 (b) 的按鍵不隨對手的跑者與總分變。

**(d)（上限，不是 (c)）：**`d-engine`——拿 AI 自己的引擎（同一個性格 L10）當玩家，只當參照列（鏡像，10.61 第二個陷阱）；不進 (c)−(b)。

**(b\*)、(c\*) 的選法（量之前固定）：**在**訓練種子**（該格）上，勝率（和局半場）最高的成員；同勝率取平均分差高的；再同取表中靠前的。**(c\*) 先排除「在訓練種子上與 (b\*) 逐位元相同」的 (c) 成員（一個從來不讀的讀者不是讀者；見「定義修訂」第三筆），再照這條規則選；全都相同時退回不排除的選法並明寫。****(b\*) 在訓練種子上的勝率若 ≥ 99%（貼上限），這一格的勝率差沒有刻度，只讀分差，並明寫。**

### 四、前置檢查與讀法（10.59、10.64、10.70）

1. 先在**訓練種子**上只跑 `divergence`（不讀勝率）：(b\*) 驅動一場、(c\*) 在每個 tick 對同一個 state 回答但不被採用，報**場級分歧率**與**點級分歧率**。**決策點（`isPoint`）＝ 我這一邊的跑者還在跑的每一個 tick**：每個這樣的 tick 都是一次「現在煞車或再等」。另報逐 tick 與活躍 tick 的分歧率。
2. 分歧率是 0 或 (b\*)(c\*) 逐位元相同：這一格讀不到東西，**回頭改定義**（量測前，記在下面「定義修訂」並先 push）。**很低但不是 0：不改定義**，改成多報有分歧的對照（雙胞胎、其餘 (c) 成員），判斷與理由寫進結果。**結構預測成立時（`exact-0` 的雙胞胎在大多數局面下不會改變按鍵），分歧率會很低甚至是 0；這時照「量不到，未知」的規矩報，不改定義去湊出分歧。**
3. 然後才在量測種子 5000..5999 讀 (c\*)−(b\*)，雙胞胎與其餘 (c) 成員對 (b\*) 用同一批種子：**勝率與分差兩個都報，各附同種子配對標準誤；(c)−(b) 一定與場級分歧率成對；另報「有分歧的那些場」的分差。**
4. 座位分開報；符號不同就不合併，也不把任何一個當互動強度。**延遲與抖動不同的格子分開報、不取平均。**
5. **判讀規則（量之前寫）：**「有互動」需要同時成立：(i) 標籤 (c\*)−(b\*) 的勝率與分差同號、各超過 2 個配對 SE（(b\*) 貼上限時只看分差）；(ii) 座位兩邊同號；(iii) 至少兩對**沒有被「(b) 太笨」污染**的雙胞胎同號同向（污染的定義：該 (b) 基底的訓練勝率低於 (b\*) 的一半）；(iv) 場級分歧率不是 0。勝率與分差反號、或座位／格子反號：報「沒有穩定的數字」。分歧率 0：報「量不到，未知」，不報 0。**結構預測的檢驗：**主格 (c\*)−(b\*) 分差若 ≤ 0（含負），報「約零或為負」並說出機制；若為正且達 (i) 到 (iv)，**預測被推翻**，照實報並查是不是 (b\*) 太笨。
6. 四個陷阱的對照（10.61）：(b) 太笨 → (b\*) 取一族最強並報它的絕對勝率，加雙胞胎與上面的污染定義（**注意：H-3 的 (b) 勝率是 0／100 的兩極，污染定義用訓練勝率會把大半成員一刀切成兩半，所以雙胞胎另外看分差**）；(c) 是不是 AI → 不是（見上）；符號翻轉 → 座位、延遲、抖動與格子分開；分歧率 → 上面第 1 到 3 點。
7. **多重比較（量之前寫）：**這一節量多個格子與多對雙胞胎。若只有少數幾格／幾對過 2 SE，不當作證據，**明寫「沒有對多重比較做校正」**。
8. **近乎支配的策略（10.70 的 D-8 教訓）要另外報：**不讀對手的強 (b) 成員對等級 1–10 的勝率與分差（`H3_PROBE_STAGE=levels`）。這是衡量標準 3（人要贏得了，但不是靠運氣）的問題，**分開報，不混進 (c)−(b)**。
