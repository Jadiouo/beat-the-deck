# Beat the Deck｜設計準則：讓 AI 好玩

版本 0.1（2026-10-06）。給之後做每一張牌的人（含 subagent）看。搭配 `SPEC.md`、`TEST_PLAN.md` 讀；第 4 到 K 張牌的小規格（`docs/cards/<id>.md`）要照這份準則寫，PR 說明要附第 6 節的清單。

這份文件由 `C-10 追與逃` 的實作一起交付，C-10 是第一個照這份準則做的牌（第 8 節）。標「推論」的地方是寫的人的判斷，不是已經量過的事實；標「建議值」的數字是起始值，牌的小規格可以改，但要寫明理由。

## 1. 為什麼要有這份文件：目標變了

前 13 張牌大多是「AI 比較強或比較弱」的競速型對抗：兩邊做同一件事，AI 只是一個更快的對手，**不是一個有趣的互動對象**。專案主人要的是後者。

新目標，照優先序（指揮官的裁定）：

1. **AI 的行為要讓人想回應它。** 玩家會想「它在幹嘛」「我要怎麼騙它」，而不是「它就是比我快」。
2. **AI 的性格要看得出來。** 同一張牌換個性格，玩起來要明顯不同。
3. **人要贏得了，但不是靠運氣。** A3 ≥ 45%、A4 ≤ 35% 是底線，不是目標。
4. **規則一句話講得完，30 到 90 秒玩得完。**

優先序的意思：第 1、2 條與第 3 條衝突時，先守第 3 條的底線（門檻不改），再在底線之內盡量滿足第 1、2 條；第 4 條是篩選牌的條件，不是拿來犧牲前三條的理由。

一個隨時可以問自己的判斷題：**把這張牌的 AI 換成「同樣強度、但行為與你的輸入無關」的版本，玩起來有差嗎？** 沒有差，就是違反第 1 條。

## 2. 五個互動類型

每張牌至少要落在一個類型裡（可以疊兩個）。小規格第一段就要寫「這張牌是 ○○型」，並回答該類型的「驗收」一欄。

### 2.1 預告型：AI 的下一步先亮出來

**一句話**：AI 在行動之前先把意圖放進 state，亮出來讓玩家看見，玩家據此規劃；輸了是自己算錯，不是被偷襲。外部實例：Into the Breach 的敵方攻擊預告、Slay the Spire 的意圖圖示。

**玩家腦中的問句**：「它下一步要去那邊，我要不要先卡位？」

**做法**
- state 加一個 `intent`（可序列化的純資料，例如 `{ kind: 'dash', target: 123, at: tick + 60 }`）。AI 先「宣告」，過了預告期才「執行」。
- 預告期內 AI 的 `actions` 只剩「維持宣告」（或明確的代價：改變意圖要扣分／要重新等一輪）。這是規則，不是 AI 的善意，所以對重播與契約測試都成立。
- 畫面要把 `intent` 畫出來（`render` 只讀 state，所以預告就是 state 的一部分，不是畫面層的魔術）。
- 預告要有「看得見但來得及」的長度：太短等於偷襲，太長等於沒有壓力。建議值 30 到 90 tick。

**驗收（可檢查）**
- 規則測試：宣告之後、執行之前，AI 的 `actions` 與 `step` 不允許悄悄改變意圖（或改變要付代價）；到期那個 tick 一定執行宣告的那個。
- 規則測試：`intent` 在 `JSON.parse(JSON.stringify(state))` 之後不變（契約 K2 會一起擋）。
- 人類模型在預告期內的反應，要能讓「看到預告才行動」勝過「不看」：用 `human-model`（有 12 tick 延遲）對同一個 AI，預告期若 ≤ 12 tick，預告等於不存在（推論：因為它看到時已經太晚）。

**適合的牌（推論）**：C-5 會動的牆（牆的預告已在規則裡，可延伸到 AI 的追擊預告）、C-10 追與逃（追方瞄準點，見第 8 節）、S-8 掃射、D-J 小偷。

### 2.2 互相讀取型：AI 依你過去的選擇預測你，你也能反制它的習慣

**一句話**：AI 的選擇是你過去選擇的函數，你的選擇也能被你自己設計成「騙它」的函數。

**玩家腦中的問句**：「它是不是看到我連出三次石頭了？那我這次出布。」

**做法**：技術模式 4.1（歷史進 state）。state 存最近 W 次（建議 W = 6）對手的選擇；`evaluate` 用這份歷史估計對手下一步的分佈，AI 選能打敗這個分佈的動作。**用有限窗口，不要用整場的累積次數**：整場累積的 AI 很難被反制，窗口式的 AI 可以被「先養習慣、再反打」騙到，這才是有趣的互動。

**驗收（可檢查）**
- 剝削測試：固定策略的假對手（永遠出同一個、或照固定循環出）對等級 10 的 AI，AI 的勝率 ≥ 80%（建議值）。證明它真的在讀。
- 反制測試：一個會「先養 W 次習慣再反打」的假對手，在養成之後的那一手勝率 ≥ 60%（建議值）。證明它可以被反讀，不是無敵。
- 這兩條都要寫成 `logic.test.ts` 裡的規則測試，用 `makeState` 直接構造歷史，不要靠跑很多局碰運氣。

**適合的牌（推論）**：H-Q 加碼（猜拳變體）、H-J 三張牌撲克（Kuhn）、H-9 吹牛骰、H-10 暗標。

### 2.3 性格可辨識型：玩家認得出「這是貪心型」並利用它

**一句話**：同一張牌，四種性格會做出不同、而且玩家能歸納出來的事。**這是這個專案最大的現成優勢**：已經有搜尋型、精準型、貪心型、賭徒型四個通用性格（SPEC 7.1），只差每張牌讓它們的差別「看得見」。

**玩家腦中的問句**：「這個只看眼前一步，我可以用遠處的東西釣它。」「這個落後就會亂衝，我先守著。」

**做法**
- 小規格要有一張表：四種性格在這張牌上各自「會做出什麼可以辨認的事」，每種寫一個可觀察的**指紋指標**（例如：貪心型的死亡率、賭徒型落後時的冒險比例、精準型的平均安全距離、搜尋型的轉彎提前量）。
- `evaluate` 的 `gain` 與 `danger` 要「分得開」：貪心型只看 `gain`、精準型先看 `danger`、賭徒型看兩者的乘積，所以這兩個數字如果寫成同一件事，四個性格就會變成同一個性格。
- 想讓某個性格有「可以被利用的習慣」，把習慣寫在小規格裡，並寫測試證明它存在（例：貪心型在兩個食物一近一遠時，永遠選近的）。

**驗收（可檢查）**
- 指紋測試：選一個指標，四個性格兩兩比較，差異至少 1.5 倍或 10 個百分點（建議值），種子 0..199。量不出差異，就改 `gain`／`danger` 的拆法，不要改性格。
- 性格表寫進小規格，PR 說明貼指紋指標的實測數字。

**適合的牌**：所有牌。尤其是 J、Q、K 與鬼牌，SPEC 7.1 允許它們混用性格。

### 2.4 導演型：AI 不搶分，而是決定你這一刻承受多少壓力

**一句話**：AI 的任務不是贏你，是在一個有規則、看得見的範圍內，決定「這一刻的壓力有多大」；玩家的樂趣是應付它。SPEC 5.1 已經允許不對稱的牌：`actions` 對兩邊可以不同，計分規則在小規格裡定義，打兩局、交換角色、兩局加總。

**玩家腦中的問句**：「它在放慢節奏等我鬆懈嗎？」「它現在是在逼我走左邊？」

**做法**
- 兩邊的角色不同：玩家做事，AI 出題（障礙、追擊、節奏）。AI 的 `actions` 是「出什麼題」，不是「怎麼贏」。
- AI 的 `gain` 是「把玩家的壓力維持在目標區間」，**不是**「玩家現在贏多少」。
- 一定要兩局交換：玩家做過導演、也做過被導演的人，才公平（SPEC 5.1）。
- 導演與橡皮筋的界線（第 3 節）：導演的強度**不可以**由分差決定；它的規則（能做什麼、多久做一次、預告多長）必須在小規格寫死，並且兩個角色的玩家看到的是同一套。

**驗收（可檢查）**
- 規則測試：把 `evaluate` 與 `actions` 裡「分差」的項拿掉（或把兩邊分數對調），AI 的選擇不變。有變，就是橡皮筋。
- 兩局加總的規則測試：兩邊角色交換後，同一個種子的兩局局面等價（C-10 用「第二局把起始位置轉 180 度」做到）。
- 指紋測試：導演的壓力曲線（例如每 10 秒的威脅數）在同一個種子下，人類模型與隨機對手面前**不一樣**——否則它沒在回應你。

**適合的牌（推論）**：C-J 關卡設計師、S-J 射手與靶、C-10 追與逃（追方是壓力的來源）。

### 2.5 互相牽制型：共用資源、搶位、堵路

**一句話**：你的最佳動作取決於 AI 現在在哪、準備做什麼；你要預測它的下一步，而不只是自己跑。

**玩家腦中的問句**：「它要搶那個，我先佔這邊。」「我走這條路它會堵我。」

**做法**：共用場地（梅花、方塊的牌天然如此）。`evaluate` 要同時算「我拿到多少」與「它能拿到多少／被我擋掉多少」，否則 AI 只是在自己的場地跑。

**驗收（可檢查）——互動強度測試**（建議值）
- 從 200 場對局裡抽 200 個局面；對每個局面，把 AI 的位置（或選擇）換成另一個合法的，用 1 步的 `evaluate` 算人類這一邊最好的動作。**至少 20% 的局面，最好的動作會因此改變。**
- 這一條是整份準則裡唯一能把「它不是只在比誰快」量成數字的測試：改變不到 20%，代表人的最佳動作與 AI 無關，兩邊其實在各打各的。

**適合的牌**：D-Q 唯一的礦、C-10 追與逃、S-5 乓、H-4 比大小（新方向）。

## 4. 三個技術模式（每張牌都會用到）

背景：`Controller.decide(state, side, tick)` 拿不到對手的歷史輸入（SPEC 7.1 的訂正已說明），而四個通用性格只透過 `actions`、`step`、`evaluate` 工作，不知道自己在玩哪張牌。所以**牌的特殊智慧只能放在牌自己的 `actions`、`evaluate`，以及牌自己的 state 裡**。以下三個模式都不需要改 `src/core/types.ts`，也不需要改契約。

### 4.1 歷史進 state，`evaluate` 做對手建模

1. 把需要的歷史**存進遊戲自己的 state**：它是可序列化的純資料，所以可以雜湊、可以重播、`JSON` 來回之後不變（契約 K2、K10 會自動檢查）。
2. 歷史的格式要小：固定長度的陣列或計數器，不要存整場的每個 tick。例：

```ts
interface RpsState {
  /** 最近 W 手：每一邊各一串，0 石頭、1 剪刀、2 布；新的在後面，超過 W 就丟最舊的。 */
  readonly history: readonly [readonly number[], readonly number[]];
  // ……
}
```

3. 在 `step` 裡**同時**更新歷史（回傳新的 state，不要改傳進來的）：

```ts
const nextHistory = [
  [...state.history[0], choice0].slice(-WINDOW),
  [...state.history[1], choice1].slice(-WINDOW),
] as const;
```

4. `evaluate(state, side)` 讀對手的那一串歷史，算對手下一手的分佈，再算「我選每個動作的期望得分」當 `gain`。**預測對手是那張牌的 `evaluate` 的工作**，通用性格只負責在 `actions` 之間挑最高的。
5. 小規格要寫：窗口 W 是多少、分佈怎麼算（建議加平滑：每個選項先加 1 次，免得前幾手過度反應）、冷啟動時（歷史不足）AI 怎麼打。
6. 測試（`logic.test.ts`）：用 `makeState` 直接塞歷史——歷史全是石頭時，AI 的 `evaluate` 對「出布」的 `gain` 必須嚴格大於其他兩個。

**為什麼不用改 core**：通用性格看不到對手上一個輸入，但看得到 state；歷史在 state 裡，所以間接「看得到」。這也是為什麼歷史必須是**公開的**：人也看得到（`render` 可以畫出最近幾手），這才是「互相讀取」。

### 4.2 pending：同時出手的牌

猜拳、暗標這種「同時選」的牌，**不可以讓 AI 看到你這一手**。

做法：兩邊先各自把選擇寫進 `state.pending`，**下一個 tick 才結算**。

```ts
interface SimultaneousState {
  readonly pending: readonly [Choice | null, Choice | null];
  // ……
}
```

AI 的 `evaluate` 在 pending 階段看不到你的選擇，只能從歷史（4.1）推測。**要寫兩條測試**：

```ts
// 4.2-a：evaluate 與 actions 對對手的 pending 是盲的
it('pending 階段：只有對手的 pending 不同，AI 側的 evaluate 與 actions 相同', () => {
  const a = makeState({ pending: [ROCK, null] }); // 0 號是人，1 號是 AI
  const b = makeState({ pending: [PAPER, null] });
  expect(game.evaluate(a, 1)).toEqual(game.evaluate(b, 1));
  expect(game.actions(a, 1)).toEqual(game.actions(b, 1));
});

// 4.2-b：四個性格的 decide 也看不出來（見下面的「模擬洩漏」）
it.each(['pathfinder', 'precise', 'greedy', 'gambler'] as const)(
  'pending 階段：%s 的決定不受對手 pending 影響',
  (name) => {
    const policy = policyByName(name);
    const params = { depth: 6, seed: 1 };
    expect(policy.decide(game, a, 1, 0, params)).toEqual(policy.decide(game, b, 1, 0, params));
  },
);
```

**模擬洩漏（這一節是寫這份文件時發現的，指揮官的原始做法沒有提到）**：4.2-a 只檢查 `evaluate` 與 `actions` 直接偷看。但搜尋型會呼叫 `step` 往前模擬 2 步以上：它先把自己的選擇寫進 pending，下一步 `step` 用「對手已經存在 state 裡的 pending」結算，`evaluate` 看到結算後的局面，就能反推出對手選了什麼。4.2-a 抓不到這件事，4.2-b（用 `decide` 當黑箱）抓得到。所以：

- 4.2-b 是必要的，不是加分。**黑箱測試是最終裁判**：不管洩漏的路徑是 `evaluate`、`actions` 還是 `step`，只要 AI 的決定因此改變，它就紅。
- 4.2-b 紅了，通常代表結算在 AI 的模擬範圍內讀了對手藏著的選擇。解法優先序：
  1. **推薦**：結算只讀「揭曉那個 tick 的 `inputs`」，兩邊同一個 tick 同時給（`step(state, inputs)` 本來就是同時），state 裡的 `pending` 只是「畫面要顯示『已鎖定』」的回音，`step` 不讀它做結算。這樣沒有任何東西可洩漏。
  2. 預設性格不要用搜尋型，並在小規格寫明（1 步看的三個性格不會穿過結算）；但這只是避開，不是修好（J、Q、K 與鬼牌可以混用性格）。
- 如果採用 1，另外加一條：「只有對手的 pending 不同的兩個 state，`step` 的下一個 state 除了 pending 之外完全相同。」

### 4.3 隱藏資訊：靠 `evaluate` 自律，而且要可驗證

SPEC 5.1 原文：「資訊限制寫在畫面層……AI 那一邊要不要也受限，寫在那張牌的小規格裡，用 `evaluate` 與 `actions` 實作，**不要偷看**。」

`evaluate(state, side)` 拿得到完整的 state，所以偷看是**可能的**；唯一的防線是測試。**每張有隱藏資訊的牌（對手的暗牌、暗骰、暗標、霧中的位置）必須有這一條規則測試**：

> 只有「對手的隱藏資訊」不同的兩個 state，該側的 `evaluate` 與 `actions` 必須相等。

```ts
it('偷看檢查：只有對手的暗牌不同，AI 側的 evaluate 與 actions 必須相等', () => {
  const a = makeState({ hidden: [CARD_K, CARD_2] }); // [人的暗牌, AI 的暗牌]
  const b = makeState({ hidden: [CARD_K, CARD_Q] }); // 只有 AI 自己的暗牌不同——這一條不該被禁止
  const c = makeState({ hidden: [CARD_A, CARD_2] }); // 只有人的暗牌不同——AI 不可以看出來
  expect(game.evaluate(a, 1)).toEqual(game.evaluate(c, 1));
  expect(game.actions(a, 1)).toEqual(game.actions(c, 1));
});
```

要點：
- 要測**兩個方向**：AI 看不到人的暗牌；如果規則也要求人看不到 AI 的（畫面層），那是 `render` 的事，在小規格寫明。
- 一樣要加黑箱版（四個性格的 `decide`，深度 6，見 4.2-b）。
- 隱藏資訊如果要被「揭曉」，揭曉的 tick 之前的所有 state，上面的測試都要成立。
- 不要用「AI 先看到、再假裝沒看到」的寫法：假裝沒有測試是擋不住的。

## 5. 等級曲線：等級 10 要「剝削」，等級 1 要「保守」

指揮官的裁定。理由：在零和均衡的牌（猜拳、Kuhn 撲克）裡，**完美的均衡策略只能把對手壓在 50%**，過不了 A4 的 35% 門檻。但人類模型有 8% 的失誤率、而且不會讀對手，所以一個**會讀對手並懲罰他**的 AI 可以遠低於 35%。

| 等級 | 行為 | 玩家的感覺 |
|---|---|---|
| **10** | 讀對手的習慣（4.1）並剝削它；反應快、每個 tick 重新決定、不亂按 | 「它在讀我」 |
| **5** | 讀得到，但慢、偶爾亂按 | 「它有時候發現，有時候沒有」 |
| **1** | 打接近均衡或保守的策略，不讀對手；反應慢、決定少、25% 亂選 | 「它好像沒在看我」 |

這同時讓 A3（人 ≥ 45%）與 A4（人 ≤ 35%）過得了，而且**正好就是「跟 AI 互動有趣」的核心**：玩家感覺得到它在讀自己，也找得到反讀它的辦法。

**實作上**：等級的差別由 `src/ai/level.ts` 的四個參數驅動：`reactionTicks`、`decideEvery`、`depth`、`epsilon`。**不要改 `src/ai/`**。牌的作者要做的是在 `evaluate` 裡讓「看得深」等於「讀得準」：

- `evaluate` 看不到等級，所以讀對手的邏輯**一律寫成「對歷史做最佳反應」**，不要寫「高等級才讀」。
- 等級 10 因為 `reactionTicks` 小（看到新鮮的歷史）、`decideEvery = 1`（每個 tick 都重新決定）、`epsilon = 0`（不亂按），所以會把最佳反應做得徹底。
- 等級 1 因為看到的是舊歷史、很少換動作、25% 亂選，所以最佳反應被稀釋，**自然變成接近隨機混合**，也就是接近均衡。
- 要「看得深」（搜尋型 `depth` 大）真的更準：`evaluate` 在 `step` 之後的 state 上要仍然有意義（歷史有被 `step` 更新），這樣往前模擬 d 步就等於多推演 d 手。
- 不是零和均衡的牌（C-10 這種追逃、競速）：同樣的原則改寫為「等級 10 把預測用到極致，等級 1 不冒險」。C-10 的等級 1 追方因為反應慢、25% 亂選，常常追丟；等級 10 追方則會精確瞄準攔截點（第 8 節）。
- 量測：每張牌一定要量 A3、A4 的**四個種子區塊**（見第 6 節）；窗口式的最佳反應（4.1）在 A4 通常有很大的餘裕，餘裕太小代表讀對手的邏輯沒有真的生效。

## 7. SPEC 第 9 節裡五張「方向本身有問題」的牌

這五張牌照 SPEC 第 9 節的一行方向做，會做出一張「AI 只是旁人」或「根本做不出來」的牌。指揮官已採納下面的替代方向。做這五張牌之前，先照這一節寫小規格，並用第 6 節的清單把關；原本的一行方向不要再用。

### 7.1 H-4 比大小

- **問題**：「猜下一張牌比較大或小，連對越多分越高，隨時可以收手」是純運氣、零互動：AI 的選擇與你的選擇無關。
- **替代方向**：**兩邊看同一串牌，各自決定收手，彼此看得見對方收了沒。**
- 類型：互相牽制型。
- 怎麼做：同一串牌（`RngState` 存在 state，兩邊共用）；每一張牌兩邊同一個 tick 各自決定「繼續」或「收手」（`inputs` 同時給，不需要 pending）；`state` 公開對方收了沒、收了多少分。
- AI 的 `evaluate`：對方已經收了 X 分時，我的 `gain` 是「超過 X 的機率」，不是自己能拿多少；對方還沒收時，才看牌的機率。
- 性格：賭徒型落後時繼續賭、精準型領先就收；這就是指紋指標。
- 小規格必須回答：連對的分數表（要讓「超過對手已收的分數」有意義）、打平怎麼辦、牌堆用完了怎麼辦。
- 風險：兩邊看同一串牌，所以運氣是對等的；贏的是「什麼時候收手」的判斷。

### 7.2 H-5 二十一點

- **問題**：「兩邊各自對同一個莊家，同一副牌」是各打各的，AI 只是旁人。
- **替代方向**：**AI 先決定停牌，你再決定跟不跟。**
- 類型：預告型＋互相牽制型。
- 怎麼做：AI 先抽到停牌為止（它停下來的那個決定是公開的、點數是否公開由小規格決定，建議公開停牌、點數也公開——這樣你的決定才有目標可打）；然後你抽牌，爆了就輸，沒爆就比點數。**兩局交換先後手**（後手有資訊優勢，不交換就不公平）。
- AI 的 `evaluate`：決定要不要停時，估計對手（你）能超過我的點數的機率；因為你還沒抽，這是從牌堆剩餘的牌算出來的，不是偷看。
- 陷阱：兩邊**不可以抽同一串牌**（SPEC 原文的「同一副牌」）。後手若抽到與 AI 同一串，就能預知自己的下一張。用 `rng.fork` 分成兩串。
- 小規格必須回答：A 算 1 還是 11、平手怎麼算、先手與後手的得分權重。

### 7.3 S-7 拔槍

- **問題**：「訊號在隨機時間出現，先按的贏，搶拍判輸；九戰五勝」是純反應競速：AI 只是反應比較快的人。
- **替代方向**：**AI 會假動作，每種性格的抽動習慣不同。**
- 類型：性格可辨識型＋互相讀取型。
- 怎麼做：state 裡有「抽動」（`twitch`）這個公開的視覺事件：AI 可以在訊號出現之前先抽動（假動作）。抽動**不算**真的訊號；搶拍仍然判輸。人要判斷「這次是真的還是假的」。
- 性格：把「抽動」做成 AI 的一個 action，由性格自己決定要不要做：貪心型常抽動（只看眼前一步，抽動的 `gain` 是正的）、精準型幾乎不抽動、賭徒型落後時才抽動、搜尋型有規律地抽動（可以被歸納）。每種的指紋指標是「抽動次數／局」。
- 反應競速檢查（第 3 節）一定要做：這張牌最容易退化回純反應。
- 小規格必須回答：抽動的長度、它會不會讓 AI 自己慢一拍（要有代價，否則 AI 永遠抽動）、人類模型怎麼處理假動作（人類模型沒有這個概念，A3、A4 要特別量）。

### 7.4 S-Q 鏡像

- **問題**：「人的左右操作每 8 秒反轉一次」只有玩家吃虧，AI 沒有參與。
- **替代方向**：**反轉由雙方輪流觸發，你可以故意擦彈逼 AI 反轉。**
- 類型：互相牽制型＋導演型。
- 怎麼做：state 裡 `mirrored: [boolean, boolean]`（兩邊各自的左右是否反轉）。觸發反轉的來源是**被擦彈的一方**對另一方：你的子彈擦過 AI 的邊緣，AI 的左右反轉一小段時間；反之亦然。反轉前要有預告（SPEC 原文）。
- 取捨：擦彈本身有風險（離子彈太近），所以逼 AI 反轉是**用風險換對方的混亂**——這就是「故意擦彈」的決策。
- AI 的 `evaluate`：反轉時它自己的 `actions` 其實也反轉了，所以 AI 的 `evaluate` 要把這件事算進去；AI 的「反轉」不能是免費的（否則只有人吃虧）。
- 小規格必須回答：反轉持續多久、能不能連續觸發、兩邊的觸發條件是否完全對稱（K12 要跑）。

### 7.5 C-Q 兩條蛇

- **問題**：`Buttons` 只有六個鍵，一個控制器操作不了兩條蛇。**這是 SPEC 的硬傷**：「AI 有兩條蛇合作包夾」若要公平，人也要有兩條，但沒有辦法操作。
- **替代方向**：**一條蛇加一個內建走位的搭檔，人也有一個。**
- 類型：互相牽制型。
- 怎麼做：每邊一條可操作的蛇，加一個**不可操作的搭檔**（例如跟在你後面三格、或沿著牆走）。搭檔的走位是 `step` 裡的固定規則（純函式、可重播），兩邊的搭檔規則**相同**。搭檔能被對方的蛇撞到（算撞身體），也能在你被包夾時幫你擋路。
- AI 與人的差別只剩「操作者的決策」：AI 會把你的搭檔當成牆來利用。
- 小規格必須回答：搭檔的移動規則、搭檔被撞會怎樣、兩個搭檔會不會互撞。
- 風險：搭檔規則若太聰明，人就變成旁觀者；若太笨，就只是多一條身體。建議值：只會沿著你過去走過的格子走，延遲 N 格。

## 8. 第一個範例：C-10 追與逃

C-10 是照這份準則做的第一張牌，細節在 `docs/cards/C-10.md`。這一節只列「準則怎麼落到這張牌」，方便之後的人對照。

- **規則一句話**：一條蛇逃、一條蛇追，兩條一樣快，兩局交換角色；逃的撐得越久、追的抓得越快，分數越高。
- **類型**：互相牽制型（主）＋預告型。追方的 AI 每 0.4 秒瞄準一個點、畫面上標出來，玩家看得見它在想什麼。導演型只沾一點邊：追方的作用是給逃方壓力，但它也搶分，所以不算純導演。
- **模式 4.1 的變形**：C-10 不需要對手歷史。追方的「想法」是 state 裡的一個欄位 `aim`（它現在瞄準的那一格），`evaluate`、`actions`、`render` 都讀它。這是預告型的做法：意圖進 state，所以它可序列化、可重播、畫面看得到，搜尋型往前模擬時它也在 state 裡，不是藏在 AI 的腦袋裡。
- **搜尋型的破綻**（SPEC 7.1 的訂正）：`pathfinder` 預測對手時假設對手維持 `actions()` 的第一個、也就是「全放開」（一直直走）；它的 `depth` 只有幾個 tick，所以這個假設在 C-10 裡真正發揮作用的地方是 `aim`：追方假設逃方「一直直走」，瞄準它 4 步之後會在的那一格，然後 0.4 秒內只往那一格追。逃方在瞄準之後轉彎，追方就撲空。這是真實、而且玩家能自己發現的破綻，不是 bug，也沒有被藏起來：說明頁只說「追的蛇每 0.4 秒瞄準一個點，畫面上有記號」，不說怎麼破。
- **這個破綻要用測試證明是真的**，不是只寫在小規格裡：把追方的預測換成「知道逃方會轉彎」的版本，對照兩者追到的位置（見 `logic.test.ts` 的「破綻」一組）。**之後的牌如果也要留一個「可被發現的破綻」，照同樣的做法：破綻 → 對照實驗 → 測試證明。**
- **一個提醒（這張牌繞了很大的路才學到）**：追逃類的遊戲，節奏與「有沒有不死的玩法」要先用最笨的腳本跑過，再談 AI。C-10 的第一版用梅花共用的評估讓追方追瞄準點，跑出來有兩個問題：追方抓不到一個只會沿著牆繞圈的腳本（共用評估的「離牆要小心」讓它不敢靠近貼牆跑的蛇），而且人類模型對等級 10 的勝率偏高（A4 約 53%，門檻 35%）。中間還有一個 `step` 的錯誤（追方走進逃方身體的判定用了轉向鎖定之前的方向，被誤判成追方自己撞死），讓那段時間的實驗數字不可信。教訓：實驗數字怪的時候先懷疑引擎，再懷疑 AI。後來的版本追方用自己的評估公式，兩邊一樣快。
- **反例對照**：不是橡皮筋（追方的瞄準週期與速度不隨分差改變）、不是作弊（`evaluate` 只看 state，沒有看輸入）、不是純反應競速（追方是在預測，不是在反應；人類模型對等級 10 的差距來自預測與決策頻率，反應延遲只是其中一項）。
