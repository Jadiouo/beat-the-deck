# Beat the Deck｜規格

版本 0.1（2026-10-06）。這份文件定義要做什麼；怎麼驗證在 `TEST_PLAN.md`，做的順序在 `TASKS.md`。

## 1. 這是什麼

一副 54 張牌的 AI 對戰街機，跑在瀏覽器裡。

- 每張牌是一個 30 到 90 秒的小遊戲。人和 AI 在同一套規則、同一個亂數種子下比分數，分數高的贏。
- 四個花色是四種遊戲機制。每個花色從 A 到 K 是同一種機制的進化：規則一張比一張多一個變化。
- 四個花色的 AI 各有一種性格，性格是決策方式的差別，不只是強弱。
- 兩張鬼牌不比輸贏：一張是人和 AI 一起亂畫，一張是規則會壞掉的實驗關。
- 贏過的牌會翻開。目標是把 54 張全部翻開。

### 1.1 不做的事（這一版）

- 不做實體機台。但輸入要抽象化，之後接實體搖桿與按鈕時不用改遊戲。
- 不做帳號、排行榜伺服器、連線對戰。進度存在瀏覽器本機。
- 不用神經網路，不做需要顯示卡的訓練。AI 全部是規則、啟發式與搜尋。
- 不用遊戲引擎與前端框架。

### 1.2 完成的定義

- 54 張牌都能玩，每張都通過契約測試與自己的規則測試。
- `npm run check` 全綠，GitHub Actions 上也全綠。
- 部署在 GitHub Pages，打開網址就能玩。
- 任何一場對局都可以用「種子＋輸入紀錄」完整重播，結果一模一樣。

## 2. 最重要的一個設計決定

**每個遊戲是一個純函式的狀態機，畫面只是它的觀察者。**

```
state₀ = init(seed, config)
stateₙ₊₁ = step(stateₙ, inputs)      // 不讀時鐘、不讀亂數以外的任何外部東西
render(ctx, state)                    // 只讀 state，不改它
```

這一個決定換來四件事：

1. **可以不開畫面跑。** 測試裡一秒可以跑幾千場 AI 對 AI，所以 AI 的強弱與性格可以用統計測試驗證。
2. **可以重播。** 種子加輸入紀錄就是一場完整的對局。
3. **AI 的預測是通用的。** 會往前看幾步的 AI 直接呼叫遊戲自己的 `step`，不用每個遊戲各寫一套模擬。
4. **好幾個 session 可以同時做不同的牌。** 每張牌只要滿足同一份契約，彼此不相干。

## 3. 技術選擇

| 項目 | 選擇 | 理由 |
|---|---|---|
| 語言 | TypeScript（strict） | 契約用型別表達，編譯期就擋掉一類錯 |
| 建置 | Vite | 零設定，輸出靜態檔 |
| 畫面 | Canvas 2D | 夠用，不需要顯示卡 |
| 測試 | Vitest | 快，與 Vite 同一套設定 |
| 端到端 | Playwright（只跑少數幾條） | 確認真的開得起來 |
| 檢查 | ESLint、Prettier | |
| CI 與部署 | GitHub Actions、GitHub Pages | |

執行期依賴：零。

邏輯解析度固定 **320×240**，整數倍放大並保持像素銳利。模擬固定 **60 tick／秒**。

## 5. 遊戲契約

```ts
// core/types.ts

export type Side = 0 | 1;                    // 0 是人，1 是 AI（測試裡兩邊都可以是 AI）

/** 抽象按鍵。所有遊戲只認這些。 */
export interface Buttons {
  up: boolean; down: boolean; left: boolean; right: boolean;
  a: boolean;  b: boolean;
}

/** 一個 tick 的輸入：兩邊各一組按鍵。 */
export type Inputs = readonly [Buttons, Buttons];

export interface Rng {
  /** [0, 1) */
  next(): number;
  /** [0, n) 的整數 */
  int(n: number): number;
  /** 分出一個獨立的子亂數，給「兩邊要拿到同一串亂數」的鏡像場地用 */
  fork(label: string): Rng;
}

export interface GameConfig {
  /** 這場的 tick 上限。到了就結束。 */
  maxTicks: number;
  /** 牌自己的參數，定義在各牌的 meta.ts */
  params: Readonly<Record<string, number>>;
}

/** state 必須是可以 JSON 序列化的純資料：沒有函式、沒有類別實例、沒有 NaN。 */
export interface Game<S> {
  readonly id: string;

  init(seed: number, config: GameConfig): S;

  /** 純函式。不可以改動傳入的 state。 */
  step(state: S, inputs: Inputs): S;

  isOver(state: S): boolean;

  /** 兩邊的分數。只有 isOver 之後的值算數。 */
  score(state: S): readonly [number, number];

  /** 贏家。平手回傳 null。預設是分數高的贏；有淘汰規則的牌可以自己定。 */
  winner(state: S): Side | null;

  /**
   * 某一邊在這個 tick 可以選的動作。動作就是一組 Buttons。
   * 即時遊戲通常回傳固定的幾種（例如停、上、下、左、右）。
   * 回合制遊戲在不是自己回合時回傳只有一個「全放開」的陣列。
   */
  actions(state: S, side: Side): readonly Buttons[];

  /**
   * 給 AI 的評估：數字越大對這一邊越好。
   * danger 是「接下來會不會死或被扣大分」的估計，0 到 1。
   * gain 是「目前領先多少」的估計，單位自訂但要單調。
   */
  evaluate(state: S, side: Side): { gain: number; danger: number };
}

/** 控制器：人或 AI。每個 tick 被問一次。 */
export interface Controller<S> {
  decide(state: S, side: Side, tick: number): Buttons;
}
```

### 5.1 契約的規則

- **決定性**：同樣的 `seed`、`config`、輸入序列，一定得到逐位元相同的 state。
- **公平**：兩邊拿到的隨機事件要對等。鏡像場地（各玩各的）用 `rng.fork` 讓兩邊拿到同一串；共用場地（搶同一批東西）天然對等。
- **一定會結束**：`maxTicks` 之內 `isOver` 必須變成 true。
- **資訊限制寫在畫面層**：像「人只看得到蛇頭附近」這種規則，state 裡是完整資訊，由 `render` 決定畫多少給人看。AI 那一邊要不要也受限，寫在那張牌的小規格裡，用 `evaluate` 與 `actions` 實作，不要偷看。
- **不對稱的牌**（例如人控蛇、AI 控障礙）：`actions` 對兩邊回傳不同的動作集合；計分規則在小規格裡定義，並且要打兩局、交換角色，兩局加總。

## 6. 一場對局

```ts
// core/match.ts
export interface MatchResult {
  winner: Side | null;
  score: readonly [number, number];
  ticks: number;
  finalHash: string;
  inputs: Inputs[];          // 重播用
}
export function playMatch<S>(
  game: Game<S>, seed: number, config: GameConfig,
  c0: Controller<S>, c1: Controller<S>,
): MatchResult;
```

`playMatch` 不碰畫面，測試直接用它。瀏覽器裡的主迴圈 `shell/loop.ts` 做同一件事，只是每個 tick 之間插入 `render`，並把真實經過的時間累積成固定長度的 tick（累加器做法，一幀最多補 5 個 tick，避免分頁切回來時爆衝）。

## 7. AI

### 7.1 四種性格

四個通用的決策方式，寫在 `src/ai/policies/`，不知道自己在玩哪一張牌，只透過契約的 `actions`、`step`、`evaluate` 工作。

| 性格 | 花色 | 怎麼選動作 |
|---|---|---|
| 搜尋型 Pathfinder | ♣ 梅花 | 往前模擬 d 步（對手假設維持上一個動作），選模擬終點 `gain − w·danger` 最高的第一步 |
| 精準型 Precise | ♠ 黑桃 | 每個 tick 都重新決定；先排除 danger 超過門檻的動作，剩下的選 gain 最高的 |
| 貪心型 Greedy | ♦ 方塊 | 只看一步，選下一個 tick `gain` 最高的動作，不看 danger |
| 賭徒型 Gambler | ♥ 紅心 | 用偏好風險的效用 `gain · (1 + r·danger)` 選動作；落後越多 r 越大 |

另有 `random`（測試的基準線）與 `human-model`（第 7.3 節）。

每張牌在 `meta.ts` 指定預設性格（依花色），也可以在小規格裡指定別的；J、Q、K 與鬼牌可以混用。

### 7.2 等級

等級 1 到 10，是性格之外的另一個軸，控制「多強」。

| 參數 | 意義 | 等級 1 | 等級 10 |
|---|---|---|---|
| `reactionTicks` | 看到的是幾個 tick 以前的 state | 18（0.3 秒） | 3（0.05 秒） |
| `decideEvery` | 每幾個 tick 才能換一次動作 | 12 | 1 |
| `depth` | 搜尋型往前看幾步決策 | 1 | 6 |
| `epsilon` | 有多少機率隨機亂選 | 0.25 | 0 |

中間等級線性內插後取整。實作在 `ai/level.ts`，回傳一個把任何性格包起來的控制器。

進度規則：每翻開 3 張牌，全域 AI 等級加 1，上限 10。每張牌另有基礎等級（A 到 3 是 1，4 到 6 是 2，7 到 10 是 3，J、Q、K 是 4），實際等級是「全域等級＋基礎等級−1」再夾在 1 到 10。

### 7.3 人類模型

`ai/human-model.ts`：一個有 0.2 秒反應延遲、每 6 個 tick 才能換動作、8% 機率按錯、只看一步的控制器。它不出現在遊戲裡，只在測試裡代替真人，用來檢查「這張牌人打得贏嗎」（見 TEST_PLAN 第 5 節）。

### 7.4 AI 的台詞

每種性格一組台詞，分「AI 贏」「AI 輸」「平手」「你連輸三場」四個情境，各至少 5 句，放 `shell/taunts.ts`。用對局的種子挑句子，所以重播時台詞也一樣。語氣是冷面的機器，不嘲笑玩家本人。

### 7.5 「AI 進化」畫面

全域等級上升時，顯示一個 5 秒的畫面：新舊兩個等級的 AI 在這張牌上對打 20 場的勝率。**這個數字要是真的**，在瀏覽器裡當場用 `playMatch` 跑出來（不開畫面跑 20 場應該在一秒內），不可以是寫死的假動畫。

## 8. 外殼

### 8.1 畫面流程

```
標題 → 牌桌（54 張牌，4 列 13 張＋2 張鬼牌）→ 選一張 → 說明頁（規則、操作、對手性格與等級）
     → 對局 → 結算（分數、AI 台詞、重播、再一次、回牌桌）
```

- 牌桌上沒贏過的牌是背面，但看得到花色與點數；贏過的翻成正面。
- 解鎖順序：每個花色要先贏前一張才能玩下一張；四個花色的 A 一開始就開放。鬼牌：翻開任意 13 張後開放 `JK-R`，翻開 40 張後開放 `JK-B`。
- 畫面上方一排 54 格的進度燈，翻開一張亮一格，鬼牌兩格用不同顏色。
- 結算頁有「看重播」：用紀錄的輸入重跑一次。

### 8.2 輸入

`shell/input.ts` 把鍵盤與 Gamepad API 都轉成 `Buttons`。

| 抽象鍵 | 鍵盤 | 手把 |
|---|---|---|
| 上下左右 | 方向鍵或 WASD | 十字鍵或左類比 |
| a | Z 或 空白鍵 | 下方按鈕 |
| b | X | 右方按鈕 |
| 暫停 | Esc | Start |

觸控：畫面下方顯示虛擬方向鍵與兩顆按鈕，寬度小於 640 像素時自動出現。

### 8.3 進度

存在 `localStorage`，鍵 `btd.v1`，內容是：每張牌的最佳分數與是否贏過、全域等級、設定。格式要有版本號；讀到不認得的版本就當成沒有存檔，不要當掉。

### 8.4 外觀

像素風，一套 16 色的固定色盤（定義在 `shell/palette.ts`，所有牌只能用這 16 色）。四個花色各有一個主色。字型用一套內嵌的點陣字，中文用系統字型並關掉平滑。設定裡有一個「掃描線」開關。音效用 Web Audio 即時合成的方波與雜訊，不放音檔；預設靜音，要玩家按過一次鍵才啟動。

## 10. 第一批十二張牌的規則

這十二張的規則在這裡寫死，測試照這裡寫。

### 梅花共同設定

- 格子 32×24，每格 10×10 像素。四周是牆。
- 蛇每 6 個 tick 走一格（一秒 10 格）。方向鍵改變方向，不能直接掉頭。
- 兩條蛇起始長度 3，人從左側中間往右，AI 從右側中間往左。
- 撞牆、撞自己、撞對方的身體：那條蛇死亡，對局結束，另一條蛇贏。兩條蛇同一個 tick 頭對頭相撞：兩邊都死，分數高的贏，同分平手。
- 場上隨時有 2 個食物。食物出現在沒有被佔用的隨機格子。

**C-A 貪食蛇對決**
- 吃到食物：分數加 1，長度加 1。
- 60 秒到：分數高的贏。

**C-2 旋轉的房間**
- 規則同 C-A。
- 每 600 tick，人這一邊的畫面順時針轉 90 度。轉之前 60 tick 畫面邊框閃爍。
- 這是畫面層的效果：state 與 AI 看到的座標不變。方向鍵永遠對應「畫面上的」上下左右，所以 `shell` 要把按鍵依目前的旋轉角度轉回世界方向再交給 `step`。旋轉角度由 tick 數算出來，放在 state 裡（`viewRotation: 0 | 1 | 2 | 3`），重播才會一致。

**C-3 紅藍食物**
- 場上隨時有紅、藍各 2 個食物。
- state 有一個「現在的正確顏色」。吃對：加 1 分、長度加 1。吃錯：扣 2 分（可以是負的），長度不變。
- 正確顏色每 480 tick 換一次；換之前 90 tick，畫面上的指示燈閃爍。

### 黑桃共同設定

- 兩邊各有一個 150×220 的場地，左邊是人，右邊是 AI，中間隔開。兩個場地的子彈由同一串亂數產生（`rng.fork('bullets')` 各自重建一次），所以完全相同。
- 玩家是半徑 3 的圓，八方向移動，速度每 tick 1.5 像素；按住 a 是慢速，每 tick 0.6 像素。
- 被打中：命中數加 1，接下來 60 tick 無敵（閃爍）。
- 分數是 `−命中數`，所以被打得少的贏。

**S-A 落雨**
- 子彈從上緣隨機位置出現，直線往下，半徑 2，速度每 tick 1.2 像素。
- 生成間隔從每 20 tick 一顆，線性縮短到第 3600 tick 時每 5 tick 一顆。

**S-2 瞄準彈**
- 落雨的子彈照舊，但間隔固定每 15 tick 一顆。
- 另外每 45 tick 從上緣隨機位置出現一顆瞄準彈：生成時朝向該場地玩家當下的位置，速度每 tick 1.6 像素，之後直線飛。
- 兩個場地的瞄準彈生成位置相同，但方向各自瞄各自的玩家。

**S-3 擦彈**
- 子彈同 S-2。
- 子彈中心與玩家中心的距離小於 10 像素而且沒有命中：這顆子彈算一次擦彈，每顆子彈最多算一次。
- 分數是 `擦彈數 − 5 × 命中數`。

### 方塊共同設定

- 格子 32×24，共用場地，兩個角色。人從左下角、AI 從右上角開始。
- 每 5 個 tick 可以走一格，四方向。兩個角色可以重疊，不互相阻擋。
- 場上有牆：用種子生成 20 道長度 2 到 5 的牆，保證所有空格連通（生成後檢查，不連通就換一組）。

**D-A 搶金幣**
- 場上隨時有 6 枚金幣，被撿走就在隨機空格補一枚。
- 走到金幣的格子就撿起來，分數加 1。兩個角色同一個 tick 走到同一枚：各得 1 分。

**D-2 背包上限**
- 金幣規則同 D-A，但撿起來是放進背包，背包最多 3 枚，滿了就撿不起來。
- 各自的基地在起始格。走到自己的基地：背包裡的金幣全部變成分數。
- 時間到時還在背包裡的不算分。

**D-3 會貶值的寶石**
- 場上隨時有 5 顆寶石。每顆出現時價值 9，每 60 tick 減 1，減到 1 之後不再降，再過 120 tick 消失並補一顆新的。
- 撿到就直接得到它當下的價值。沒有背包規則。
- 畫面上寶石的大小或亮度要看得出價值。

### 紅心共同設定

- 回合制的牌不用 60 tick 的即時輸入：輪到某一邊時，那一邊按 a 或 b 做決定，另一邊的輸入被忽略。每個決定最多等 300 tick，超過就自動選保守的那個選項（小規格裡指定）。
- AI 做決定前固定等 45 tick，讓人看得清楚發生什麼事。

**H-A 貪心骰**
- 兩邊輪流進行回合，人先。
- 自己的回合裡：按 a 擲一顆六面骰。擲到 2 到 6：加進「這回合的累積」，可以繼續擲。擲到 1：這回合的累積歸零，回合結束。按 b：把這回合的累積存進總分，回合結束。
- 先達到 50 分的贏。兩邊回合數要相同：人先到 50 之後，AI 還有最後一個回合可以追。
- 上限 40 個回合（各 20），到了就比總分。
- 超時的自動選項是 b。

**H-2 引信**
- 共 5 局，兩邊同時玩，各自一條引信，長度相同（同一個亂數）。
- 每一局：按住 a，這一局的累積每個 tick 加 1；放開就把累積存進總分，這一局對自己結束。引信長度是 120 到 600 tick 之間的均勻隨機數，玩家看不到；累積的 tick 數達到引信長度就爆炸，這一局的累積歸零。
- 一局開始後 60 tick 內還沒按下 a 的，這一局得 0 分。
- 兩邊都結束後，顯示這一局的引信長度，進下一局。
- 5 局總分高的贏。

**H-3 懸崖**
- 共 5 局。跑道長 300 像素，懸崖在右端。
- 兩邊同時從 0 出發，自動以每 tick 1 像素前進，速度每 30 tick 增加 0.1。按下 a 開始煞車：以每 tick 0.05 的減速度減速到停。
- 停下來的位置沒超過 300：這一局的得分是位置的整數部分。超過 300：掉下去，這一局 0 分。
- 每一局的跑道長度相同；為了不讓人背起來，每局的起始速度從 0.8 到 1.2 之間隨機，兩邊相同。
- 5 局總分高的贏。

## 11. JK-R 一起亂畫

這張牌回答的是「人和 AI 一起在同一張畫布上隨便畫，最後會出現什麼」。它不用任何影像生成模型，只用處理器。

- 畫布 320×240，16 色色盤。人控制一支筆：方向鍵移動，按住 a 下筆，b 換顏色。
- 三支 AI 筆同時在畫，各有一種行為：
  - **跟隨者**：延遲 1 秒重複人的筆跡，但對畫布中心做鏡射。
  - **填充者**：沿著一個由種子決定的流場走，遇到已經有顏色的地方就轉彎，傾向把空白填滿。
  - **唱反調的**：往離人的筆最遠的空白區域移動，用與人當下顏色互補的顏色。
- 人停筆超過 3 秒，三支 AI 筆也慢慢停下來。這張牌的核心是「一起」，不是 AI 自己畫完。
- 90 秒結束。結束畫面可以把畫布存成 PNG，檔名帶種子。
- 同樣遵守契約：畫布是 state 的一部分（320×240 的色號陣列），所以同一個種子加同一串輸入會畫出同一張圖。`score` 固定回傳 `[0, 0]`，`winner` 固定回傳 `null`，玩過一次就算翻開。
